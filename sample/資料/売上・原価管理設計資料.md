# 売上・原価管理設計資料

## 1. この資料の目的

この資料は、DeepExperienceにおける売上・原価・利益の管理方針・データ構造・計算ロジックを整理するための資料です。

予約単位での収支を「予約時点の見込み」と「ツアー後の実績」の2段階で管理し、チャネル手数料・決済手数料・施設費を含めた正確な利益把握を実現します。

## 3. 初期MVPの基本方針

### 3-1. MVPで実現すること

- チャネル（OTA・自社サイトなど）ごとに手数料率を設定できる
- 予約ごとにチャネル手数料率を上書きできる
- Bokun取込時、検証要チャネル（現状Airbnb）の予約は「金額確認待ち」として保留し、担当者がOTA管理画面で実額を確認・修正して確定できる
- 決済方法ごとに手数料率を設定できる
- TourOptionごとに施設費（固定＋人数課金）を設定できる
- 予約単位で以下を管理できる
  - グロス売上（ゲストからの受取総額）
  - チャネル手数料・決済手数料
  - ネット受取額（グロス − 手数料）
  - ガイド報酬（精算レコードから連携）
  - 施設費（変動部分：参加人数ベース）
  - 見込み収支・実績収支
- 催行回単位で施設費（固定部分）を記録できる

### 3-2. MVPではやらないこと

- 会計ソフト・ERP・決済システムとの自動連携
- 催行回単位の施設費（固定部分）を複数予約へ自動配賦
- 月次・年次での損益計算書の自動生成
- 消費税・源泉徴収の自動計算
- 為替レートの自動更新

### 5-3. 施設費・経費項目（施設マスター連携）

施設費および都度経費は、**「施設マスター・原価項目設計資料」で定義する施設マスター＋経費項目**で管理する（データ構造の正本は同資料。本資料はそれを原価計算へ取り込む側）。

旧「施設費マスター（TourOptionごと・固定／変動の2分類）」は廃止し、以下へ**一本化**する。

- **施設マスター**：施設単位で登録し、複数の**経費項目**（費用区分4種＋支払区分A〜D）を持つ。TourOptionへは**経費項目単位でN:M紐付け**する。
- **単発経費**：施設に属さない都度経費は、TourOptionへ自由入力する（マスター登録なし）。
- 紐づけた経費項目の単価は**予約時にスナップ固定**し、以後は不変。原価単価の変更はTourOptionバージョンを増やさない（§6-2 ※2）。

**費用区分と原価バケツの対応**（本資料の原価計算は従来の「固定／変動」バケツで継続する）

| 費用区分（施設マスター・原価項目設計資料 §5） | 本資料での扱い | 記録粒度 |
| --- | --- | --- |
| 固定費（人数問わず一定） | 施設費（固定）相当 | 催行回単位（§8） |
| 変動・人数固定／変動・スライド | 施設費（変動）相当 | 予約単位（人数依存） |
| 変動・完全変動（実費精算） | 実績はガイド精算経由の実費。見込みは目安金額（参考・非拘束） | 実費に準ずる |

- **単発経費**も上表と同じく費用区分に応じて固定／変動の扱い・記録粒度に従う。
- **支払区分A〜D**は精算ルート（誰が立替えるか）の分岐であり、**原価計上額そのものは支払区分に依らない**。ツアー運営経費（施設費・単発経費）は実体側で**1回だけ**計上し、ガイドが立替えた場合（B/C/D）の精算はガイドへの返金として扱う（**ガイド報酬の各種経費には含めず**、二重計上を防ぐ）。立替・精算の詳細はガイド手配設計資料を参照。

## 6. 売上・原価の計算構造

### 6-1. 売上の定義

| 区分 | 定義 | 計算式 |
| --- | --- | --- |
| グロス売上 | ゲストが支払った総額 | 販売金額（予約レコード）。自社・OTA経由とも予約レコードの販売金額を基準とする |
| チャネル手数料 | OTA・チャネルへの支払い | グロス売上 × チャネル手数料率 |
| 決済手数料 | 決済サービスへの支払い | グロス売上 × 決済手数料率 ＋ 固定手数料 |
| ネット受取額 | Deepの実際の受取額 | グロス売上 − チャネル手数料 − 決済手数料 |

### 6-2. 原価の構成

| 区分 | 内容 | 参照元 |
| --- | --- | --- |
| ガイド報酬 | 時給×時間＋各種経費（通勤交通費・その他のガイド固有経費を含む。施設費・単発経費の立替返金は含めない） | ガイド精算レコード |
| 施設費（変動）| 参加人数 × 変動単価 | 施設マスター（経費項目） |
| 施設費（固定）| 1催行回あたりの固定費 | 催行回施設費実績レコード（※1） |
| 単発経費 | 施設に属さない都度経費。費用区分に応じ固定／変動の扱い | TourOption（単発経費） |
| ゲスト立替経費 | ゲスト分の立替（元本は売上と相殺。ただし立替分に課金される手数料は実コスト）| ガイド精算レコード |

> **ガイド向け表示との二層分離**：本表は**内部の原価計上**。ガイドへの支払表示では、立替分（施設費・単発経費）も含めて全額を業務委託「報酬」として見せる（ガイド向け表示と内部原価は別レイヤー。詳細は施設マスター・原価項目設計資料 §11）。立替分はガイド報酬科目ではなく施設費・単発経費として1回だけ計上し、二重計上しない。

**※1 グループツアーにおける原価の配賦について**

施設費（固定）とガイド報酬はいずれも催行回単位で発生します。複数の予約が1つの催行回を共有するグループツアーでは、**原価の記録は催行回単位**としつつ、月次の予約別表示での扱いを以下のとおりとします（記録粒度＝催行回単位／表示粒度＝予約別、を分けて扱います）。

- **プライベートツアー**（1予約＝1催行回）：予約収支レコードに直接記録します
- **グループツアー（ガイド報酬）**（複数予約が1催行回を共有）：ガイド報酬は催行回単位で発生しますが、月次表示では各予約へ人数按分（予約人数÷催行回合計人数）で配賦して表示します
- **グループツアー（施設費）**（複数予約が1催行回を共有）：MVPでは催行回単位で記録し、予約単位への配賦は対象外とします。催行回単位の収支は別途確認できるようにします。配賦方法（参加人数比・予約数均等割りなど）はMVP後に決定します

**※2 原価集計の束ね鍵とTourOptionバージョン（TourOption ID）の扱い**

収支のTourOption別集計は、**束ね鍵を「TourOptionコード（商品系統）」に固定**します。提供内容の改訂で同一コードに複数のTourOptionバージョン（別TourOption ID）が並立しても、集計の既定単位はコード（系統）であり、各TourOptionバージョンは**ドリルダウン時のみTourOptionバージョン（TourOption ID）に分解**して表示します（TourOptionバージョンの常時列・生ID表示はしない）。

- 原価表連動の粒度も**TourOptionコードのタブを前提に維持**します（原価表タブ名＝TourOptionコードに一致、商品・販売設計資料の原価レコード参照）。コード単位のタブから原価を取り込む現行運用を変えません。
- TourOptionバージョン別に原価が異なる場合（提供内容改訂で含む物・所要時間等が変わったケース）は、**コードタブの値をシステム内の原価レコード側でTourOptionバージョン（TourOption ID）ごとに上書き**して差を表現します。これはOD-1（TourOptionバージョンの増分トリガーは提供内容の実体改訂時のみ／価格・原価は同一ID内の有効期間付き子レコードで管理）と整合します。
- 予約は予約時点のTourOptionバージョン（TourOption ID）にピン留めされるため、収支・原価は予約時点のTourOptionバージョンに紐づくスナップショット値で記録され、TourOptionバージョン変更後も書き換えません（TourOptionバージョン固定）。集計上の系統横断はコードで、TourOptionバージョン差の確認はドリルダウンで行います。

### 6-3. 利益の計算

| 区分 | 計算式 | 用途 |
| --- | --- | --- |
| 粗利 | ネット受取額 − ガイド報酬 − 施設費（変動）− 施設費（固定）− 単発経費<br>＝ グロス売上 − チャネル手数料 − 決済手数料 − ガイド報酬 − 施設費 − 単発経費 | チャネル手数料・決済手数料を引いたあとの実質利益。チャネル手数料は立替分を含むグロスに課金される |

> **注意**：グロス売上ベースの粗利（グロス売上 − ガイド報酬 − 施設費）は使用しない。チャネル手数料・決済手数料を除いたネット受取額を起点にすることで、Deepが実際に受け取る金額を基準とした利益を管理する。

**ゲスト立替経費の扱い（重要）**：ゲスト立替は、グロス売上（＋）とガイド報酬（−）の両方に同額で含まれるため、その**元本部分は粗利上で相殺**されます。ただしOTAチャネル手数料・決済手数料は**立替分を含むグロス全額**に課金されるため、立替分にかかる手数料（＝立替額 × チャネル手数料率＋決済手数料率）は相殺されず、**Deepの実コストとして粗利に反映**されます。

したがって粗利は上式（ネット受取額起点）でそのまま計算し、**ゲスト立替を売上・原価から個別に除外してはいけません**（除外すると立替分の手数料コストまで消えて粗利を過大評価する）。

> 例：立替¥2,000・チャネル手数料20%の場合、立替の元本¥2,000は売上とガイド報酬で相殺されるが、それに課金される手数料¥400は実コストとして粗利を¥400押し下げる。

## 7. 予約収支レコード

### 7-1. 目的

予約単位での収支を「見込み」と「実績」の2段階で管理するレコードです。予約確定時に見込み収支を記録し、ツアー後に実績収支を更新します。

### 7-2. 管理項目

#### 識別

| 項目 | 内容 |
| --- | --- |
| 収支レコードID | システムで自動生成する内部ID |
| 予約ID | 紐づく予約レコードのID |
| TourOption ID / コード | 紐づくTourOption。**TourOption ID＝予約時点のTourOptionバージョン（予約作成時にピン留め、TourOptionバージョン固定で書き換えない）／TourOptionコード＝商品系統の不変識別子**。収支のTourOption別集計の**束ね鍵はコード（系統）**で、TourOptionバージョン（ID）は[ドリルダウン時のみ分解](#6-2-原価の構成)（§6-2 ※2参照） |
| 催行回ID | 紐づく催行回（グループツアーの場合は複数予約が同一IDを参照） |
| 参加人数 | 予約時の参加人数（変更後は更新） |
| 取込ステータス | （Bokun取込予約のみ）金額確認待ち / 確認済み。検証不要チャネルは取込時点で確認済み相当 |
| 収支ステータス | 見込み計算済み / 実績入力待ち / 実績確定。取込ステータスが「金額確認待ち」の間は収支計算を保留する |

#### 売上（予約確定時に記録）

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 販売金額（グロス） | ゲストが支払った総額 | 予約レコードから |
| チャネルID / チャネル名 | 予約が入ったチャネル | |
| チャネル手数料率 | 適用する手数料率 | チャネルマスターから初期設定。予約ごとに上書き可 |
| チャネル手数料額 | 販売金額（グロス）× 手数料率で自動計算 | |
| Bokun取込値（販売価格・チャネル手数料） | Bokun取込時の元値を保持する | 監査証跡。金額確認で上書きせず別に残す。確認後の値とのズレ検証に使う |
| 確認者 / 確認日時 | 金額確認待ちを「確認済み」にした担当者と日時 | Bokun取込・検証要チャネルのみ |
| 決済方法 | 使用した決済方法 | |
| 決済手数料率 | 適用する手数料率 | 決済方法マスターから |
| 決済手数料額 | 決済金額 × 手数料率 ＋ 固定手数料で自動計算 | |
| ネット受取額 | 販売金額 − チャネル手数料 − 決済手数料で自動計算 | |

#### 原価（見込み・予約確定時）

| 項目 | 内容 | 参照元 |
| --- | --- | --- |
| ガイド報酬（見込み）| ガイド精算レコードの見込み合計 | 精算レコード |
| 施設費・変動（見込み）| 参加人数 × 経費項目の変動単価 | 施設マスター（経費項目） |
| 施設費・固定（見込み）| 固定費の経費項目（プライベートツアーのみ直接記録）| 施設マスター（経費項目） |

| 単発経費（見込み）| TourOptionに紐づく単発経費。予約時にスナップ固定 | TourOption（単発経費） |
| ゲスト立替経費（見込み）| 参考値。精算レコードから | 精算レコード |

| 項目 | 内容 | 参照元 |
| --- | --- | --- |

| 施設費合計（実績）| 変動 ＋ 固定で自動計算 | |
| 単発経費（実績）| 実費精算型は実費、それ以外はスナップ値 | TourOption（単発経費）／精算レコード |
| ゲスト立替経費（実績）| 参考値。精算レコードから | 精算レコード |

#### 利益（自動計算）

| 項目 | 計算式 |
| --- | --- |
| 粗利（見込み）| ネット受取額 − ガイド報酬（見込み）− 施設費合計（見込み）− 単発経費（見込み）|
| 粗利（実績）| ネット受取額 − ガイド報酬（実績）− 施設費合計（実績）− 単発経費（実績）|

## 9. 収支ステータスと更新フロー

### 9-1. 収支ステータス

| ステータス | 意味 |
| --- | --- |
| 見込み計算済み | 予約確定後、見込み収支が記録された状態 |
| 実績入力待ち | ツアー実施後、ガイド精算の確定待ち |
| 実績確定 | ガイド精算が確定し、実績収支が計算された状態 |

### 9-2. 更新フロー

```
予約確定
  └→ 予約収支レコード作成
       ・販売金額（グロス）を記録
       ・チャネル手数料・決済手数料を自動計算
       ・ネット受取額を自動計算
       ・ガイド報酬・施設費の見込みを反映
       ・見込み粗利を自動計算
       ステータス：見込み計算済み

変更・キャンセル発生時
  └→ 予約収支レコードを更新
       ・販売金額・参加人数の変更を反映
       ・手数料・施設費（変動）を再計算
       ・見込み収支を更新

ツアー実施後（ガイド精算確定後）
  └→ 実績原価を更新
       ・ガイド精算レコードの実績確定値を反映
       ・施設費（固定・実績）を催行回施設費実績レコードから反映
       ・実績粗利を自動計算
       ステータス：実績確定
```

### 9-3. Bokun取込時の金額確認フロー

Bokunから予約を自動取込する際、チャネルによっては販売価格・チャネル手数料が実額とズレて連携される（現状はAirbnb）。これらのチャネルはチャネルマスターで「金額検証要否＝ON」とし、取込時に金額確認のステップを挟む。

```
Bokun自動取込
  ├─[金額検証要否 OFF]→ 取込ステータス：確認済み相当
  │                     → 通常どおり見込み収支を計算（ステータス：見込み計算済み）
  │
  └─[金額検証要否 ON ]→ 取込ステータス：金額確認待ち
                        ・Bokunの販売価格・手数料を「Bokun取込値」として保持
                        ・★収支計算は保留（ネット受取額・見込み収支は未計算）
                        │
                        ↓ 担当者がOTA管理画面で実額を照合・修正
                        │
                        確認済みにして確定
                        ・確認後の販売価格・チャネル手数料を確定
                        ・確認者・確認日時を記録
                        ・ここで初めて見込み収支を計算（ステータス：見込み計算済み）
```

**設計ルール：**

- **保留方式**：金額確認待ちの間は見込み収支を計算しない。間違ったBokun金額が収支一覧・集計に混ざらない。
- **収支一覧・集計画面**は「金額確認待ち」を集計対象から除外する。除外件数を画面上に表示し、確認漏れ（＝売上の抜け落ち）に気づけるようにする。
- **監査証跡**：Bokun取込値は上書きせず別フィールドで保持し、確認後の値と並べて差異を検証できる。
- **再sync保護**：「確認済み」になった予約はBokun再syncの自動上書き対象外とする（または再度「金額確認待ち」に戻して再確認を促す）。

- 確認待ち件数が1減る。

## 11. 初期MVPの対象外

| 項目 | 理由 |
| --- | --- |
| 会計ソフト・ERP連携 | 別途連携設計が必要 |
| 月次損益計算書の自動生成 | 集計基盤が必要。MVP後 |
| 施設費（固定）の複数予約への自動配賦 | グループツアーの複雑なケース。MVP後に設計 |
| 消費税・源泉徴収の自動計算 | 税務設計が別途必要 |
| 為替レートの自動更新 | 外部API連携が必要 |
| Bokun金額の検証不要化（完全自動連携） | Bokunからの取込予約は手動で金額確認する（[9-3](#9-3-bokun取込時の金額確認フロー)）。OTA実額との完全自動照合は将来拡張 |
| アフィリエイト・Resellerの手数料計算 | 下記「将来拡張」参照 |
| グループツアーの原価配賦（ガイド報酬を除く） | ガイド報酬は人数按分で月次表示に反映済み（§6-2）。施設費（固定）等の予約配賦方法はMVP後に決定 |

## 11-2. 将来拡張：アフィリエイト・Reseller

現在のチャネルマスターにはOTAと自社サイトのみを想定しています。将来的にアフィリエイトパートナーやResellerが加わる場合、チャネルマスターの「手数料種別」フィールドを起点に以下のように拡張します。

| 手数料種別 | 概要 | 計算方式 |
| --- | --- | --- |
| OTA | KlookやViatorなどのプラットフォーム | グロス売上 × 手数料率 をDeepが負担 |
| アフィリエイト | 集客パートナー（ブログ・インフルエンサーなど）| 予約ごとにアフィリエイト手数料を別途記録。チャネル手数料とは別の費用科目として管理 |
| リセラー | 卸売り販売するパートナー事業者 | Deepはネット金額（卸値）を受け取る。グロス（エンドユーザーの支払い）とネット（Deep受取）を分けて記録する必要がある |
| 自社 | 自社サイト・直接販売 | 手数料なし |

MVPで必要な拡張口は以下のとおりです（MVPでは実装しないが、設計上フィールドを確保します）：

- チャネルマスターの「手数料種別」フィールド → 既にMVPで追加済み
- 予約収支レコードへのアフィリエイト手数料額フィールド → MVP後に追加
- Reseller向けのグロス・ネット分離記録 → MVP後に設計

## 13. まとめ

売上・原価管理では、予約収支レコードを中心に「グロス売上」と「ネット受取額」の両方を記録します。チャネル手数料・決済手数料をネット受取額の計算に組み込み、ガイド報酬・施設費と合わせて粗利を算出します。

見込み（予約確定時）と実績（ツアー後確定）の2段階管理により、採算判断と実績確認の両方に対応します。施設費は固定（催行回単位）と変動（人数課金）を分けて管理し、グループツアーでの固定費配賦はMVP後の設計とします。
