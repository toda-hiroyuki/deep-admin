# 運営管理画面設計資料

## 1. この資料の目的

この資料は、DeepExperienceの新システムにおける「運営管理画面」の設計方針と画面構成を整理するための資料です。

運営管理画面の目的は、運営担当者が日々の案件（予約・ガイド手配・催行回）を効率よくさばけるようにすることです。

---

#### 予約ステータス

**ツアー実施前**

| ステータス | 意味 |
|---|---|
| 確定待ち | リクエスト予約で、Deep側の確認が完了していない状態 |
| 確定予約 | 予約として確定し、運営対応対象になっている状態 |
| キャンセル済み | 予約がキャンセルされた状態 |
| 無効 | 運営側の誤登録により業務対象外とした状態 |

**ツアー実施後**

| ステータス | 意味 |
|---|---|
| Completed | ゲストがツアーに参加し完了した状態 |
| No-show | ゲストが当日現れなかった状態。予約はキャンセルされていない |
| Guide_No-show | ガイドが当日現れなかった状態。Deep側の責任 |
| Incompleted | ゲストがツアーを途中で離脱・未完了となった状態 |

#### 催行ステータス（催行回レベル）

| ステータス | 意味 |
|---|---|
| 未催行 | ツアー日前。まだ実施されていない状態 |
| Operated | 正常に催行された状態 |
| Not Operated | 予約はキャンセルされていないが催行されなかった状態。No-show・Guide_No-showが主なケース |
| Aborted | 催行途中で中断された状態 |
| Cancelled（中止） | 催行前にキャンセルされた状態 |

#### 催行回紐付けステータス（予約 × 催行回）

| ステータス | 意味 |
|---|---|
| 未紐付け | 催行回がまだ割り当てられていない |
| 仮紐付け | 催行回を仮で割り当てた状態。変更可能 |
| 確定紐付け | 催行回への紐付けが確定し、ガイド手配を開始できる状態 |

#### 手配状況（催行回レベル・画面表示用）

| 表示ラベル | 条件 |
|---|---|
| 未手配 | 手配レコードが存在しない、または全件「未手配」 |
| 募集中 | 1件以上が「募集中」で、確定・アサイン済みが0件 |
| アサイン済み | 1件以上が「アサイン済み」で、確定が0件（ガイド確認待ち）|
| 一部確定 | 複数ガイド手配で、確定が1件以上あるが全件未確定 |
| 確定済み | 必要なすべての手配レコードが「確定」 |
| 要確認 | キャンセルが発生した場合、または予約変更（日時変更・増員・減員）により再手配要否フラグがON |

#### 手配ステータス（手配レコード個別）

| ステータス | 意味 |
|---|---|
| 未手配 | まだ誰もアサインしていない |
| 募集中 | 募集通知をガイドアプリに送信済み。応募を受け付けている状態 |
| アサイン済み | 運営がガイドをアサイン済み。ガイドのアプリ確認待ち |
| 確定 | ガイドがアプリで確認ボタンを押し、アサインが確定した状態 |
| キャンセル | アサインが取り消された状態 |

#### 精算ステータス

| ステータス | 意味 |
|---|---|
| 見込み設定済み | 原価表から見込み経費・時給が反映された状態 |
| 実績入力待ち | ツアー後、ガイドによる実績入力を待っている状態 |
| 確認待ち | ガイドが入力済みで、運営側の確認を待っている状態 |
| 確定 | 運営が承認し、精算内容が確定した状態 |

#### 支払いステータス（予約レベル）

| ステータス | 意味 |
|---|---|
| 未払い | まだ入金がない状態 |
| Partially Paid | 総請求額の一部のみ入金済み（追加支払い未回収・代理店分割入金等を含む）|
| 支払い済み | 総請求額が全額入金済みの状態 |
| 支払い不要 | キャンセル等で請求が発生しない状態 |
| 部分返金済み | 一部返金が完了した状態 |
| 全額返金済み | 全額が返金済みの状態 |
| Chargeback / Disputed | チャージバック申請または支払い争議が発生した状態 |
| Penalty Applied | 運営都合キャンセルによりOTAからペナルティを受けた状態。売上がマイナスになる |
| 要確認 | 入金状況が不明・照合待ちの状態 |

※ 上記9値が支払いステータスの正式な値セット（正本）。ただし**予約登録時点では4値（未払い / 支払い済み / 支払い不要 / 要確認）のみ**を選択可とし、返金・係争・分割入金系を含む残り（Partially Paid / 部分返金済み / 全額返金済み / Chargeback・Disputed / Penalty Applied）へは**登録後に入金照合・返金処理等を経て更新可**とする。

#### 返金ステータス

| ステータス | 意味 |
|---|---|
| 未処理 | 返金が必要だが、まだ完了していない。進捗はメモ欄で管理 |
| 完了 | 返金が完了した |
| 不要 | 返金が発生しない（キャンセル料率100%など） |
| OTA返金済み（Deep対応不要） | OTA側が返金処理済み |
| 要確認 | OTA側の返金状況が不明・確認待ち |
| 特別対応中 | Deep側が独自の追加対応を進めている |

※ 上記6値が返金ステータスの正式な値セットであり、他資料の返金ステータスはこの定義を正とする。

#### 運営確認ステータス（予約レベル・MVP）

予約ステータスとは別に、ツアー運営部の確認・対応状態を管理する（定義の正本は予約登録 設計資料§13-3）。予約一覧の「データ不備」タブで表示・更新する。

| ステータス | 意味 |
|---|---|
| 未確認 | 予約登録後、まだ運営が確認していない |
| 確認中 | 内容確認中 |
| 確認済み | 必要情報の確認が完了している |
| 要対応 | 追加対応が必要 |
| 対応完了 | 必要対応が完了している |

※ データ不備タブでの表示・確認済み化はMVP。全予約タブの常時列としての表示・予約詳細での編集UIは将来フェーズ（予約登録§20-1/§20-2）。

### 2-2. ステータス連動フロー

予約確定からツアー終了までの主要なステータス遷移を示します。

```
予約登録
  ↓
[予約ステータス]
  確定待ち ─── Deep確認 ──→ 確定予約
  （即時確定の場合は直接「確定予約」）
  確定予約 / 確定待ち ──→ キャンセル済み（キャンセル発生時）

  ↓（ツアー実施後）
  確定予約 ──→ Completed / No-show / Guide_No-show / Incompleted

  ↓（確定予約になると）

[催行回紐付けステータス]
  プライベートツアー: 未紐付け → 確定紐付け（催行回自動生成と同時）
  グループツアー:     未紐付け → 仮紐付け → 確定紐付け

  ↓（確定紐付けになると）

[手配状況]
  募集経由:   未手配 → 募集中 → アサイン済み → 一部確定 / 確定済み
  直接アサイン: 未手配 → アサイン済み → 一部確定 / 確定済み

  ↓（変更・キャンセル発生時）
  要確認（再手配要否フラグON）または キャンセル済みに遷移

  ↓（ツアー実施後）

[精算ステータス]
  見込み設定済み → 実績入力待ち → 確認待ち → 確定
```

---

### 2-3. 主な注意点

- 予約ステータスが「確定予約」であっても、支払い完了を意味しない。支払い状態は支払いステータスで別管理する
- 手配ステータスが「確定」でも、再手配要否フラグがONの場合は催行回レベルで「要確認」と表示される
- 精算ステータスの「確定」はガイドへの支払い確定であり、予約の確定とは別管理

## 3. 主要画面

### 3-1. 予約一覧

**目的**: 運営担当者が全予約案件を把握し、対応が必要な案件を素早く特定する。

**タブ構成**

予約一覧は4タブ「全予約 / データ不備 / 重複疑い / 取込ログ」で構成する。

- **データ不備**: システム自動付与のデータ不備フラグが立つ予約の抽出（運営は内容確認のうえ確認済みにして解除。手動付与ボタンは無い）
- **重複疑い**: 重複ペア判定にかかった予約
- **取込ログ**: OTA/Bokun等の取込結果（社内予約ID無し＝予約未生成の取込失敗の行のみ「手動登録」リンク）

各サブビューの要件は予約登録§20-4〜§20-6を参照。

**表示列**

| 列 | 内容 |
|---|---|
| 予約ID | 社内予約番号 |
| 予約日 | 予約が作成された日付 |
| ゲスト名 | 予約者名 |
| TourOptionコード / 名称 | 対象ツアー |
| ツアー日時 | 日付・開始時間 |
| 参加人数 | 大人・子供の内訳 |
| 予約元 / チャネル | 自社サイト / OTA名など |
| 予約ステータス | 確定待ち / 確定予約 / キャンセル済み / 無効 / Completed / No-show / Guide_No-show / Incompleted |
| 催行回紐付け | 未紐付け / 仮紐付け / 確定紐付け |
| 手配状況 | 未手配 / 募集中 / 確定済み / 要確認など |
| データ不備フラグ | 予約データに不備・確認事項がある場合に表示（TourOptionマッピング失敗・必須項目未入力など）|

**絞り込み条件**

| 条件 | 選択肢 |
|---|---|
| 予約ID / 外部予約番号 | テキスト入力。社内予約IDまたはOTA予約番号・取込元システム予約IDで検索（お客様問い合わせ時の素早い特定用） |
| 予約ステータス | 確定待ち / 確定予約 / キャンセル済み / 無効 / Completed / No-show / Guide_No-show / Incompleted |
| ツアー日 | 日付範囲指定 |
| 予約日 | 日付範囲指定（予約作成日）|
| TourOption | TourOptionコードまたは名称 |
| 予約元 / チャネル | 自社サイト / OTA / 問い合わせ / 旅行会社 |
| 手配状況 | 未手配 / 要確認など |
| データ不備フラグ | ON/OFF |

**ソート**: 列ヘッダークリックで昇順/降順を切り替え可能。対象列：ツアー日時・予約日。デフォルトはツアー日時昇順

### 3-2. 未割り当て一覧

**目的**: 催行回にまだ紐付いていない予約を抽出し、割り当て漏れを防ぐ。割り当て後は本一覧から外れる。

**表示単位**: 予約単位（催行回紐付けステータスが「未紐付け」の予約のみ）

**表示列**

| 列 | 内容 |
|---|---|
| 予約ID | 外部予約番号を併記 |
| ゲスト名 | |
| TourOptionコード / 名称 | 対象ツアー |
| ツアー日時 | 希望ツアー日・開始時間 |
| 参加人数 | |
| ゲスト言語 | |
| 予約元 / チャネル | 自社サイト / OTA名など |

**ソート**: ツアー日時昇順（デフォルト。ツアー日が近い順）

**操作**: 各行の「割り当て」ボタンから予約割り当て画面（§3-3）へ遷移する。

### 3-3. 予約割り当て

**目的**: 未紐付けの予約を催行回へ仮紐付けする。未割り当て一覧から遷移する。

**画面構成**

#### ① 割り当て対象の予約情報
対象予約の予約ID・ゲスト名・参加人数・TourOption・希望ツアー日時・ゲスト言語・予約元/チャネル・現在の紐付けステータスを表示する。

#### ② 割り当て方法（2方式）

**(a) 既存催行回に紐付け**
- 同一TourOption ID（=同一TourOptionバージョン）・同一ツアー日時・同一言語が完全一致する既存催行回のみを候補として表示。束ね鍵はTourOption ID（TourOptionバージョン）＋ツアー日時＋ゲスト言語であり、提供内容ハッシュは不採用。同一TourOptionコードでもTourOptionバージョン（TourOption ID）が異なれば別催行回として扱い、同乗（合流）は不可
- 空き枠が対象予約の人数に満たない回（満員・枠不足）は選択不可
- 候補を選択して仮紐付けを実行

**(b) 新規催行回をインライン作成して紐付け**
- 既存催行回に入らない場合のみ使用。TourOption・ゲスト言語は予約から継承（変更不可）し、ツアー日・開始時刻を入力
- 継承するTourOptionは、対象予約が保持するTourOption ID（予約固定TourOptionバージョン）をそのまま継承する。現時点の最新TourOptionバージョンではなく、予約作成時にピン留めされたTourOptionバージョンで催行回を生成する（生成される催行回のTourOption IDフィールドにこの固定TourOptionバージョンを設定）
- 定員はTourOptionのリソース設定値を初期表示
- 作成と同時に仮紐付けされる

**注意**: 催行回の単独新規作成画面は設けない（MVP対象外）。催行回の新規作成は割り当て操作時のインライン作成（本画面、または予約詳細（§3-8）の割り当て操作）のみとする。仮紐付け→確定紐付けへの切替は催行回詳細画面（§3-5）で行う。

### 3-4. 未手配一覧

**目的**: ガイドがアサインされていない催行回を抽出し、手配漏れを防ぐ。

手配が必要な状態とは、催行回紐付けが「仮紐付け」または「確定紐付け」で、かつ手配状況が「未手配」または「要確認」の催行回を指す。

**表示単位**: 催行回単位（グループツアーで複数予約が紐づく場合も1行で表示）

**表示列**

| 列 | 内容 |
|---|---|
| 催行回ID | |
| ツアー日時 | 日付・開始時間 |
| TourOptionコード / 名称 | 対象ツアー |
| 参加人数 | 催行回全体の合計人数 |
| 予約数 | 紐づく予約の件数 |
| 手配状況 | 未手配 / 要確認 |
| 変更理由区分 | 要確認の場合：日時変更 / 増員 / 減員 |
| ガイド要件 | 対応言語（同一催行回内は同一言語に限定）|
| 催行回紐付け | 仮紐付け / 確定紐付け |

**絞り込み条件**

| 条件 | 選択肢 |
|---|---|
| ツアー日 | 日付範囲指定（デフォルト：今日以降） |
| TourOption | TourOptionコードまたは名称 |
| 手配状況 | 未手配 / 要確認 |
| 催行回紐付け | 仮紐付け / 確定紐付け |

**ソート**: ツアー日昇順（デフォルト）

### 3-5. 催行回詳細画面

**目的**: 催行回単位で予約・ガイド手配・紐付け状況を一覧・操作する。催行回一覧・当日翌日案件一覧・未手配一覧の行クリックから遷移する共通の詳細ハブ画面。

**アクセス元**: 催行回一覧・当日/翌日案件一覧・未手配一覧（行クリック）

**画面構成（セクション）**

#### ① 催行回基本情報
- 催行回ID
- TourOptionコード / 名称
- ツアー日時
- 定員 / 現在人数

### 3-11. 変更・キャンセル処理

**目的**: 予約の変更・キャンセルを処理し、各所への反映内容を確認・記録する。予約詳細から遷移する。

**アクセス**: 予約詳細の「変更・キャンセル処理を行う」ボタン → 種別選択画面 → 各専用処理画面へ分岐

---

#### 3-11-0. 種別選択画面

発生元区分と変更理由を入力してから種別を選択する。

- 発生元区分：ゲスト都合 / 運営都合 / 第三者都合（OTA・旅行代理店など）
- 変更理由：テキスト入力
- 種別選択：日時変更 / 人数変更 / キャンセル → 各専用画面へ遷移

---

#### 3-11-1. 日時変更処理

**ステップ：**
1. 変更後ツアー日・開始時間の入力
2. 金額確認（変更前販売金額 / 変更後合計金額（手動）/ 差額 / 価格差額対応方針：追加請求 / 差額返金 / 変更なし）
3. 反映確認（リソース再確保 / 旧催行回無効・新催行回生成 / 再手配要否フラグON）
4. 処理実行

**TourOptionバージョン固定の注意**: 日時変更で生成・付け替える新催行回は、予約が保持するTourOption ID（予約固定TourOptionバージョン）を継承する（日時変更ではTourOptionバージョンを書き換えない）。束ね鍵はTourOption ID（TourOptionバージョン）＋ツアー日時＋ゲスト言語のため、同一TourOptionコードでもTourOptionバージョン（TourOption ID）が異なる既存催行回へは合流（同乗）できない。

---

#### 3-11-2. 人数変更処理（増員・減員）

**ステップ：**
1. 変更後参加人数の入力（増員 / 減員を自動判定）
2. 金額確認
   - 増員：追加請求額（手動入力）/ 変更後合計金額
   - 減員：返金額（手動入力）/ 変更後合計金額
3. 反映確認（リソース追加確保または解放 / 催行回人数更新 / 再手配要否フラグON）
4. 処理実行

**増員時の追加請求ステータス（AC_STATUS）**: 増員（および直販扱いのOTA当日現地増員）で追加請求が発生する場合、決済リンク発行と回収状況を以下のステータスで管理する（値の正本は本節）。OTA経由の通常増員はOTA次回精算で調整しDeep対応不要のため、本ステータスの対象外。

| ステータス | 意味 |
|---|---|
| 未送付 | 追加請求レコードは作成済みだが、決済リンクを未送付の状態 |
| 請求済み（未払い） | ゲストへ決済リンクを送付済みで、入金待ちの状態 |
| 支払い済み | 追加請求分の入金が完了した状態 |
| 期限切れ | 決済リンクの有効期限が切れた状態。新リンクの再発行・URL更新が必要 |
| 取消 | 追加請求自体を取り消した状態 |

**返金ステータスの責務分界**: §2-1の返金ステータス6値は、減員・キャンセルの**処理結果として作成された返金レコード**に対する進捗管理であり、その表示・更新は変更・キャンセル履歴／予約詳細（§3-8 ⑥支払いサマリー・⑦変更・キャンセル履歴）側の責務とする。本変更・キャンセル処理画面では返金額の確定までを扱い、6値ステータス自体の遷移管理は行わない。

---

#### 3-11-3. キャンセル処理

**ステップ：**
1. キャンセル内容確認（予約情報サマリー表示）
2. 金額確認（変更前販売金額 / キャンセル料率（手動入力）/ キャンセル料（自動計算）/ 返金額（自動計算））
3. 反映確認（リソース解放 / 催行回無効化または人数更新 / ガイド手配キャンセル）
4. 処理実行

## 5. 初期MVPで対象外にするもの

| 項目 | 理由 |
|---|---|
| ダッシュボード / KPIサマリー | 売上・稼働率などの集計表示は後続フェーズで扱う |
| ガイドアプリの高度な機能 | 確認ボタン・応募・実績入力はMVP対象。ガイドの稼働カレンダー管理・自動レコメンドなどの高度機能は将来フェーズ |
| 複数案件の一括操作 | MVP後に対応 |
| CSVエクスポート | MVP後に対応 |
| スマートフォン最適化 | 初期はPC利用を前提とする |

## 6. 初期MVPの完了条件

以下ができる状態を完了条件とします。

- 予約一覧から対象案件を特定し、詳細を開けること
- 予約ステータス・手配状況・ツアー日で絞り込めること
- 予約詳細で基本情報・ゲスト情報・手配情報・支払い情報を一画面で確認できること
- 未手配・要確認の案件をリストアップし、手配画面に遷移できること
- 催行回の人数・手配状況を一覧で確認できること
- 当日・翌日のツアーを1画面で確認でき、未手配アラートが表示されること
- 変更・キャンセル処理を実行し、履歴として記録できること
- 精算確認画面で見込みと実績を照合して承認できること
- OTA入金照合で入金レコードと社内予約を紐付け、差異を記録できること
