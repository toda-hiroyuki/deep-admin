# 施設マスター・原価項目設計資料

## 1. この資料の目的

この資料は、DeepExperienceにおける**施設マスター**と**原価項目（経費）**の管理方針・データ構造・計算ロジックを整理するための資料です。

提携施設への支払い、ツアー中にガイドが立て替える都度経費（入場料・飲食・土産など）、ガイドの人件費を、**すべて「原価」として一貫した仕組みで管理**することを目的とします。原価は以下の **3区分** で構成されます。

- **① 施設経費**（施設マスターから選択）
- **② 単発経費**（TourOptionへ自由入力）
- **③ ガイド人件費**（アサイン時に確定）

対象画面は **施設管理（admin）** と **TourOption「09 経費」タブ** です。

## 3. 全体像 — 原価の3区分

### 3-1. 3区分の概要

| 区分 | 発生元 | 登録方法 | 確定タイミング |
| --- | --- | --- | --- |
| **① 施設経費** | 提携施設・観光地（実在の場所） | 施設マスターに登録された経費項目を**選択して紐づけ**（マスター必須） | 予約時にスナップ固定 |
| **② 単発経費** | 特定施設のない少額コスト | TourOptionに**直接入力**（マスター登録なし） | 予約時にスナップ固定 |
| **③ ガイド人件費** | 担当ガイド | アサイン時に自動計算（ガイドごと）。入稿時は内部の仮値で試算 | アサイン時に確定 |

### 3-2. 設計の基本原則

- **施設系はマスター必須、単発は自由入力**（§7-1／§7-2）。
- 原価サマリー（目安）は **① 施設経費 ＋ ② 単発経費 ＋ ③ 想定人件費（試算）** で算出する（§9）。
- ①② は予約時点でスナップ固定し、以後は不変（§7-3）。③ の実値はアサイン時にガイドごと確定する（§8-2）。

## 4. 施設マスター

施設（提携施設・観光地など実在の場所）を登録し、その施設で発生する**経費項目を複数**ぶら下げて管理します。例：「大阪城」が施設、「入場料」が経費項目。

### 4-1. 施設レコード

| 項目 | 説明 | 備考 |
| --- | --- | --- |
| 施設ID | システムで自動採番する内部ID | コード体系はMVPでは持たない（内部IDのみ） |
| 施設名 | 例：嵐山竹林体験センター／大阪城 | 価格などを名前に含めない |
| カテゴリ | 神社・仏閣／体験施設／飲食店／宿泊施設／観光スポット／農園・自然／その他 | |
| 都道府県 | 47都道府県マスターから選択 | |
| 住所 | 市区町村以降 | |
| 連絡先電話番号 | | 任意 |
| 連絡先メールアドレス | | 任意 |
| 担当者名 | | 任意 |
| 支払区分（デフォルト） | A〜D（§6）。経費項目の初期値として継承 | 経費項目ごとに個別上書き可 |
| 備考 | | 任意 |
| ステータス | 有効／無効 | |
| 登録日／最終更新 | システム記録 | |

> **暫定（要確定）**：施設一覧の「外部」区分は**提携／非提携の区別**とする（外部＝非提携先。例：大阪城）。意図の最終確認が必要（§10-2）。非提携先もマスターに登録する前提。

### 4-2. 経費項目レコード

1つの施設に複数の経費項目を持てます。

| 項目 | 説明 | 備考 |
| --- | --- | --- |
| 経費項目ID | システムで自動採番する内部ID | |
| 所属施設ID | 紐づく施設 | |
| 項目名 | 例：入場料／竹細工体験料／音声ガイド | |
| 費用区分 | 固定費／変動・人数固定／変動・スライド／変動・完全変動（§5） | |
| 支払区分 | A〜D（§6）。施設デフォルトを継承し個別上書き可 | |
| 単価／基本料金 | 固定費・人数固定で使用 | |
| 人数帯テーブル | 変動・スライドで使用（§4-3） | |
| 目安金額 | 完全変動（実費精算型）で使用。単一値・参考・原価確定には使わない（§5-2） | |
| 備考 | 適用条件・注意事項 | 任意 |

### 4-3. 人数帯テーブル（スライド用）

費用区分が「変動・スライド」のとき、人数帯ごとの1人あたり単価を持ちます。

| 項目 | 説明 |
| --- | --- |
| 最大人数（しきい値） | この人数までは当該単価を適用。最終行は空欄＝上限なし |
| 単価（円/人） | 当該人数帯の1人あたり単価 |

例（着物レンタル料）：5名まで¥2,000／15名まで¥1,800／それ以上¥1,500。

## 5. 費用区分（4種・2系統）

費用区分は4種を維持しつつ、性質で **2系統** に分かれます。

### 5-1. 一覧と計算ロジック

| 費用区分 | 系統 | 原価の計算 | 入力するもの |
| --- | --- | --- | --- |
| 固定費 | 単価確定型 | 金額一定（人数問わず） | 基本料金 |
| 変動・人数固定 | 単価確定型 | 人数 × 単価 | 単価／人 |
| 変動・スライド | 単価確定型 | 人数帯にマッチした単価 × 人数 | 人数帯テーブル（§4-3） |
| 変動・完全変動 | **実費精算型** | 催行後にガイドが入力した実費 | 目安金額（参考・単一値） |

- **単価確定型**（固定費／人数固定／スライド）：事前の単価がそのまま見込原価・確定原価になる。
- **実費精算型**（完全変動）：事前は目安金額のみ。確定はガイドが催行後に実費入力（§5-2）。

### 5-2. 実費精算型（完全変動）と目安金額

金額が事前に読めないコストは「実費精算型」とし、**品目としては登録するが金額は確定値を持たない**。

- **目安金額**：単一値・参考・非拘束。**原価確定には使わない**。
- **事前提示**：催行回詳細／ガイドアサイン画面の「想定経費リスト」に、品目名＋目安金額を表示し、ガイドが*何を・いくらくらい*立て替えるかを事前に把握できるようにする。
- **確定**：催行後にガイドが実費をガイド精算レコードへ入力 → 実績原価となる（ガイド手配設計資料の立替精算と接続）。
- 登録先は、施設系なら施設マスター、単発なら TourOption 自由入力（§7-2）。

## 6. 支払区分 A〜D

「誰が・いつ払うか」を表す精算ルートの分岐です。施設にデフォルトを持たせ、経費項目ごとに個別上書きできます。

| 区分 | 意味 | 立替 |
| --- | --- | --- |
| **A** | 施設へ月末一括（会社払い） | 立替なし・Deepが直接支払い |
| **B** | 登録施設へ都度払い | ガイド立替 → 後日精算 |
| **C** | 登録施設外へ都度払い | ガイド立替 → 後日精算 |
| **D** | ガイド自身の経費 | 精算対象 |

B・C・D のガイド立替は、売上・原価管理設計資料 §6-2 の立替経費・ガイド精算へ接続する。

## 7. TourOptionへの紐付け（「09 経費」タブ）

### 7-1. 施設経費（マスターから選択・経費項目単位 N:M）

- TourOption 入稿時に**施設を選び、その施設の経費項目から使うものだけを個別に選択**する。
- 紐付けの粒度は **経費項目単位（経費項目 ⇔ TourOption は N:M）**。施設ごと一括ではない。
  - 例：大阪城の経費項目に「入場料／特別展／音声ガイド」があるとき、TourOptionには「入場料」だけを乗せ、他は外せる。
- 紐づけた経費項目は TourOption 側からは解除（×）のみ。単価などの編集は施設マスター側で行う（§7-3）。

### 7-2. 単発経費（自由入力）

- 特定の施設がない少額コスト（たこ焼き・土産代・ツアー中の移動交通費など）は、施設マスターに登録せず **TourOptionに直接入力**する。
- 入力項目：経費名／費用区分（§5）／支払区分（§6）／金額／備考。
- 「たこ焼き：1000円」のように**価格を名前に含めない**（金額は金額欄へ）。
- 単発経費にも実費精算型（完全変動）を指定でき、その場合は目安金額を持つ（§5-2）。

### 7-3. 価格スナップショット方針

| フェーズ | 挙動 |
| --- | --- |
| 入稿〜未予約 | TourOption は施設マスターを**参照**。見込原価は**常に最新マスター単価**を反映 |
| 予約発生時 | その時点の単価を**予約原価レコードへスナップ固定**。以後マスターを変更しても予約済みは不変 |

- マスターの単価を変更すると、未予約の見込原価には自動反映されるが、予約済みには影響しない。
- **原価単価の変更は TourOption バージョンを増やさない**（原価は商品条件スナップショット〔L2〕の対象外）。バージョン分裂を避けるため、原価は予約時にのみ固定する。
- 例：マスター¥600→¥700 に変更 → 未予約の見込は¥700／変更前に入った予約は¥600のまま。

## 8. ガイド人件費

ガイド人件費は **2層** で扱う。

### 8-1. 交通費は2種類

「交通費」は性質が異なるため、置き場所を分ける。**混在させると二重計上になる**。

| 種類 | 中身 | 置き場所 |
| --- | --- | --- |
| ツアー中の移動交通費 | スポット間の電車・タクシー等。ツアー内容で決まり、誰が担当でも同額 | **② 単発経費**（§7-2） |
| ガイドの通勤交通費 | 集合場所まで＋解散場所から。担当ガイドの出発地で変わる | **③ ガイド人件費**（本節） |

### 8-2. 実値（アサイン時・ガイドごと）

- 担当ガイド確定時に、**実時給 × 所要時間 ＋ 実通勤交通費 ＋ その他経費**で算出する。
- これが精算・実績原価になる（適用時給・立替精算はガイド手配設計資料を参照）。

### 8-3. 想定人件費の内部試算（仮値・ガイド非表示）

アサイン前の利益試算のため、TourOption に**想定人件費（試算用・内部）**を持つ。

- 構成：**想定時給 × 想定所要時間 ＋ 想定通勤交通費**。
  - 想定所要時間はツアー時間、想定時給は標準時給を初期値にできる。
  - **その他経費は試算から除外**する。
- 性質：
  - **内部のみ・ガイドには一切表示しない**（想定経費リスト・精算画面に出さない）。
  - あくまで**仮値・非拘束**。実値（§8-2）が確定値であり、仮値は実績に影響しない。
  - 用途は運営の利益試算のみ。
- 想定通勤交通費は「1ガイドあたり往復 × 想定ガイド数」で持つ（貸切は1ガイド）。

## 9. 原価サマリー（試算）

TourOption「09 経費」タブで、催行人数を指定して原価を試算する。

```
原価試算合計 ＝ ① 施設経費合計 ＋ ② 単発経費合計 ＋ ③ 想定人件費（試算）
```

- ①② は催行人数で計算（人数固定・スライドは人数依存）。予約時にスナップ固定（§7-3）。
- ③ は内部・ガイド非表示の仮値（想定時給×所要時間＋想定通勤交通費、その他経費は除外／§8-3）。
- ③ の実値はアサイン時にガイドごと確定し、そちらが精算・実績原価になる。

**試算例（10名催行・貸切3時間）**

| 区分 | 内訳 | 金額 |
| --- | --- | --- |
| ① 施設経費合計 | 入場料¥1,500/人 ＋ 竹細工¥2,000/人 × 10名 | ¥35,000 |
| ② 単発経費合計 | ツアー中移動交通費¥800/人 × 10名 | ¥8,000 |
| ③ 想定人件費（試算・内部） | 想定時給¥2,000×3h ＋ 想定通勤交通費¥3,000 | ¥9,000 |
| **原価試算合計** | | **¥52,000** |

> **暫定（要確定）**：実費精算型（完全変動）の目安金額は、別行で原価試算合計に加算する（確定値ではない旨を明示。§10-2）。

## 10. 既存資料との関係・未決事項

### 10-1. 既存「施設費マスター（売上・原価管理設計資料 §5-3）」との関係

- 既存資料の施設費マスターは **TourOptionごと・固定／変動の2分類**で定義されていた。
- 本資料の施設マスターは **施設単位・経費項目を複数・4分類＋支払区分**を持つ新モデルであり、§5-3 を**置き換えた**。
- → 売上・原価管理設計資料 §5-3 を本モデルへ**一本化済み（2026-06-19）**。同資料側に「費用区分→原価バケツ（固定／変動）の対応表」を追加し、原価計算・粗利に**単発経費**を反映、支払区分による立替返金の二重計上防止を明記した。

### 10-2. 暫定方針（要確定）

以下は**暫定**であり、確定ではない（見直し可）。

1. **実費精算型（完全変動）の原価サマリー扱い**：目安金額を原価試算合計に**含める**。ただし「目安・確定値ではない」と分かる**別行で明示**する（§9）。
2. **施設マスターの「外部」区分**：**提携／非提携の区別**とする（外部＝提携契約のない施設。例：大阪城）。※意図の最終確認が必要。
3. **単発経費「交通費（ガイド）」の整理**：当該品目を**「ツアー中移動交通費」に改名**して②単発経費に残す（軽量・改名のみ／仕組み化はしない）。通勤交通費は③ガイド人件費で別管理（§8-1）。品目名は自由入力のまま。
4. **施設ID／経費項目IDのコード体系**：**内部IDのみ（コード化しない）**。業務コードは持たない（既存方針＝ガイドID以外はコード化しない、に沿う／§4-1・§4-2）。

## 11. ガイド向け表示と内部原価計上の二層分離

ガイド向け画面での「報酬・経費の見せ方」と、本資料・売上・原価管理設計資料が扱う「内部の原価計上」は**別レイヤー**である。両者を取り違えると矛盾に見えるため、分離を明文化する。

### 11-1. 二層分離の原則

| レイヤー | 何を表すか | 主な所在 |
| --- | --- | --- |
| **ガイド向け支払表示** | 業務委託として**ガイドに支払う総額**。時給報酬・通勤交通費・ツアー経費（立替・実費）を含め、**すべて「報酬」**として表示する | ガイド管理画面（報酬管理／支払明細） |
| **内部の原価計上** | Deepの粗利計算のための**原価科目**。ガイド報酬（時給×時間＋通勤＋その他）／施設費／単発経費に**分離**し、立替分は実体側で1回だけ計上（二重計上しない） | 本資料・売上・原価管理設計資料 §6-2 |

- ガイドに渡る**総額** ＝ 内部の「ガイド報酬原価」＋「施設費・単発経費（ガイドが立替えた分）」。ガイド画面では総額を一括で「報酬」と呼ぶが、内部ではこれを科目へ振り分けて計上する（**同じ金額を二重に数えない**）。
- 売上・原価管理設計資料 §6-2 の「立替返金はガイド報酬に含めない」は**内部計上レイヤー**の規定であり、ガイド向け表示で立替を報酬に含めることと矛盾しない。

### 11-2. ガイド向け立替費目の呼称と内部科目・支払区分の対応

| ガイド表示の費目 | 内容 | 内部の原価科目 | 主な支払区分 |
| --- | --- | --- | --- |
| ゲスト分立替経費 | ゲスト分の入場料・飲食等をガイドが立替 | 施設費／単発経費（変動） | B・C |
| ガイド分立替経費 | ガイド自身の入場料等（1名分） | 施設費／単発経費 | B・C・D |
| その他（実費精算） | 事前に金額が読めない実費（ツアー中の臨時移動等／費用区分＝完全変動） | 単発経費（実費） | B・C・D |
| 通勤交通費 | 集合場所まで＋解散場所から（ツアー経費ではない） | ガイド報酬（時給×時間＋**通勤**＋その他） | D |

- ガイド画面の「ツアー経費（立替・実費）」は、**ゲスト分立替経費＋ガイド分立替経費＋その他（実費精算）**をまとめた**表示上の総称**。内部では施設費・単発経費の各科目に分かれる。
- 支払区分A（施設へ月末一括・会社払い）は**ガイドの立替が発生しない**ため、ガイド向け立替費目には現れない。

### 11-3. ガイド入力の2分類（自動反映／毎回入力）

ツアー経費はすべてTourOption原価設定（施設経費／単発経費）から品目が**自動反映**される。ガイドが金額入力するのは限られる。

| 区分 | 対象 | ガイドの操作 |
| --- | --- | --- |
| 自動反映 | 単価確定型（固定費／変動・人数固定／変動・スライド） | 金額は設定どおり自動表示。**差異があるときだけ「修正」（金額＋理由）→運営承諾** |
| 毎回入力 | 実費精算型（変動・完全変動）／通勤交通費 | 目安を参考に**実費を入力** |

- 原価設定に無い経費は申請できない（ガイドが任意の経費を自由追加する導線は設けない）。領収書は任意。

### 11-4. その他経費（運営登録・ツアー非紐付け）

研修交通費・翻訳費など**ツアーに紐づかない経費**は、件数が少なく定型でないため**運営が登録**する。ガイドは**閲覧専用**で確認し、内容に相違があれば「相違を報告」する（ガイドからの申請フローは設けない）。これらも業務委託報酬として支払う。§8-3 の「その他経費」は内部の想定試算からは除外するが、実績はこの運営登録分として報酬へ算入する。

### 11-5. ガイド向け個人情報・詳細資料の表示タイミング

| 段階 | 旅行者名 | 行程の詳細資料 |
| --- | --- | --- |
| 募集中／応募中／確認待ち（アサイン確定前） | **非表示**（「アサイン確定後に表示」） | **非表示**（行程は要点のみ） |
| 確定／実施中／完了（アサイン確定後） | 表示 | 表示（詳細資料リンク） |

- 参加人数・注意事項（車椅子対応等）は応募判断に必要なため、確定前でも表示する。
- 支払明細（実績）では氏名を出さずツアー名で識別してよい（運用裁量）。

### 11-6. 用語対応とガイド画面での扱い

- 呼称対応：ガイド表示「ツアー経費（立替・実費）」＝内部「施設費（変動）／単発経費」、「その他（実費精算）」＝内部「変動・完全変動」、「自動反映」＝内部「マスター参照（予約時スナップ固定）」。
- **「想定通勤交通費」（§8-3・内部の利益試算専用・ガイド非表示）** と、ガイドが入力・表示する**「通勤交通費（実値）」**（§8-2）は**別物**。資料・画面では混同を避けるため、前者は「想定通勤交通費（内部試算）」と明記する。
- 予約コード（OTA予約コード）・TourOptionの商品/プレビューURL・行程要点は、ガイドの案件照合・準備のためガイド画面に表示してよい。
- 予約時スナップ固定（§7-3）は内部の原価レコード挙動であり、ガイド画面での可視化は必須としない。
