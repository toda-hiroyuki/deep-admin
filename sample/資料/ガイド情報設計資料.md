# ガイド情報設計資料

## 1. この資料の目的

この資料は、DeepExperienceにおけるガイドのマスター情報の管理方針・データ構造・管理画面を整理するための資料です。

「誰に依頼できるか」を判断するための基礎データ（基本情報・資格・対応エリア・言語・報酬単価など）を一元管理し、ガイド手配・催行回管理・原価管理の参照元として機能します。

---

## 2. 初期MVPの基本方針

### 2-1. MVPで実現すること

- ガイドを1件ずつ登録・管理できる
- 基本情報（氏名の漢字/カタカナ/ローマ字・連絡先・個人情報）を管理できる
- 資格・スキルランクを管理できる
- 報酬単価（時給）をガイドごとに設定できる（ガイドマスタが持つ報酬は基本時給1本）
- 特定TourOptionで基本時給と異なる単価が必要な場合は、個別単価の専用レコードは持たず、アサイン時に運営が「適用時給」を手動で上書きする運用とする
- 銀行口座情報・インボイス登録番号を管理できる
- 対応エリア・対応言語を管理できる
- 採用時の情報を採用担当が入力し、手配担当が参照できる
- ガイドの稼働状況（アクティブ / 一時停止 / 退会）を管理できる
- ガイド手配・催行回設計の参照元として機能できる

### 2-2. MVPではやらないこと

- ガイドの稼働カレンダー・スケジュール自動管理
- ガイドの空き状況チェックの自動化
- ガイドへの自動通知・オファー送信
- 報酬・支払い処理の自動化
- ガイド向けポータル（将来フェーズ）
- 契約書類・署名ファイルの管理
- ガイドの評価・レビュー管理

## 5. 報酬単価

### 5-1. 業務委託報酬の考え方

ガイドは業務委託契約のため、報酬総額は以下の構成になります。

```
業務委託報酬（総額） ＝ 時給 × 稼働時間 ＋ 交通費など経費
```

**時給**は計算の根拠として使用する単価です。ガイドへ報酬内訳を示す際に分かりやすい単位として管理します。経費（交通費・施設費など）は別途精算する想定で、支払い計算処理はMVP後に設計します。

将来のB2Bテーラーメイドツアーなど案件によっては「1ツアーあたりの固定報酬」になる場合もあり得ますが、時給×時間で表現できるケースが大半なため、基本単位は時給とします。必要な場合に備えて報酬単位フィールドを持ち、将来「1ツアーあたり」への切り替えも可能にします。

### 5-2. ガイドレコードの報酬単価項目

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 報酬単価（時給・税込） | このガイドの現在の基本時給 | 時給履歴レコードの最新レコードと一致する。参照用 |
| 報酬単位 | 1時間あたり（デフォルト）/ 1ツアーあたり | 将来のB2B対応に備えてフィールドを持つ |

### 5-3. ガイド時給履歴レコード

時給を変更するたびに新しいレコードを追加し、変更履歴を保持します。既存レコードは上書きしません。

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 履歴ID | システムで自動生成する内部ID | |
| ガイドID | 対象ガイドのID | |
| 時給（税込） | 変更後の時給 | |
| 適用開始日 | この時給が有効になる日付 | |
| 変更理由メモ | 変更の背景・理由 | 任意 |
| 変更担当者 | 変更を行った運営担当者 | |
| 変更日時 | レコードの作成日時 | |

**運用方針：**
- 時給を変更する場合は既存レコードを編集せず、新しい履歴レコードを追加する
- 最新の履歴レコードが現在の適用時給となる
- ガイドレコードの `報酬単価（時給・税込）` は最新の履歴レコードの値と同期させる（参照用）
- アサイン時に手配レコードに適用時給を記録するため、過去の手配に遡及しない

## 7. ガイド対応エリアレコード

1ガイドが複数エリアに対応できるため、別レコードで管理します。スプレッドシートではエリアごとに列を持つ構造ですが、新システムでは1行1エリアのレコードとして管理します。

| 項目 | 内容 |
| --- | --- |
| 対応エリアID | レコードのID |
| ガイドID | 対象ガイドのID（G-NNN形式） |
| エリア名 | 対応可能なエリア。**Phase 1は都道府県または都道府県内の主要都市単位**（例：石川県、金沢市、大阪府、京都市）|
| 備考 | 対応条件・制約など（任意） |

既存スプレッドシートのエリア列（東京・大阪・京都など約50項目）から初期データを移行します。Phase 1では都道府県または都道府県内の主要都市単位で移行する。

**将来フェーズ**: マーケティング観点（旅行者の検索エリア）やガイドの活動範囲観点など、用途別に異なるエリア粒度に分割する予定。その際はエリアマスターテーブルを導入し、TourOptionおよびガイドの対応エリアと紐付ける構造に移行する。

## 8. ガイド対応言語レコード

1ガイドが複数言語に対応できるため、別レコードで管理します。スプレッドシートでは言語ごとに列を持つ構造ですが、新システムでは1行1言語のレコードとして管理します。

| 項目 | 内容 |
| --- | --- |
| 対応言語ID | レコードのID |
| ガイドID | 対象ガイドのID（G-NNN形式） |
| 言語 | 対応可能な言語（例：英語、中国語、韓国語） |
| 習熟度 | ネイティブ / 流暢 / 日常会話レベルなど（任意） |

既存スプレッドシートの言語列（英語・中国語・韓国語・スペイン語・ドイツ語・フランス語・ロシア語・トルコ語・ポルトガル語）から初期データを移行します。

## 10. 管理画面・機能

### 10-1. ガイド一覧画面

必要機能：

- ガイド一覧表示（稼働状況フィルター付き）
- ガイドID・氏名（漢字/カタカナ/ローマ字）での検索
- エリア・言語・スキルランクによるフィルター
- 稼働状況別の絞り込み

### 10-2. ガイド詳細画面

タブ構成：

| タブ | 主な内容 | 主な編集者 |
| --- | --- | --- |
| 基本情報 | ガイドID、氏名（漢字/カタカナ/ローマ字）、連絡先、WhatsApp参加状況、個別連絡希望 | 全担当者 |
| 個人情報 | 国籍、生年月日、住所 | 全担当者 |

## 11. 初期MVPの対象外

| 項目 | 理由 |
| --- | --- |
| ガイドの稼働カレンダー管理 | 空き状況の自動化は将来フェーズで設計 |
| 報酬・支払い処理の自動化 | 会計・支払い基盤との連携が必要。MVPでは手動 |
| ガイドへの自動通知 | 通知基盤が必要。将来拡張 |
| ガイドの評価・レビュー管理 | MVP後の品質管理フェーズで対応 |
| ガイド向けポータル（自己受注） | ガイド手配設計の将来拡張として扱う |
| 支払い情報のアクセス権限管理 | 初期はシステム内で全担当者が参照可能とし、将来フェーズで権限設計を行う |
| 契約書類・署名管理 | 外部ツールとの連携が必要 |

## 12. 初期MVPの完了条件

- ガイドを登録・編集できる
- ガイドIDをシステムで自動生成できる
- ガイドIDを一意の識別子として管理できる
- 氏名を漢字・カタカナ・ローマ字それぞれで管理できる
- 連絡先（Tel・Email）を管理できる
- WhatsAppコミュニティ参加済・個別連絡希望フラグを管理できる
- 国籍・生年月日・住所を管理できる
- 全国案内士資格・地域案内士資格の有無を管理できる
- ガイドスキルランクを管理できる
- 基本報酬単価（時給・税込）を管理できる
- 時給を変更するたびに履歴レコードを追加でき、変更履歴を保持できる
- ガイド詳細の報酬単価タブで現在の時給と変更履歴を確認できる
- 銀行口座情報（銀行名・支店番号・支店名・口座種別・口座番号・口座名義）を管理できる
- インボイス登録番号を管理できる
- 対応可能エリアを複数登録できる
- 対応可能言語を複数登録できる
- 採用情報（面接日・職業・面接時info）を記録でき、手配担当が参照できる
- 稼働状況（アクティブ / 一時停止 / 退会）を管理できる
- 非アクティブなガイドは手配対象から除外できる
- 退会後もガイド情報を保持し、過去の手配履歴を参照できる

---

## 13. まとめ

ガイド情報は、手配判断・原価管理・催行回管理の参照元となるマスターデータです。初期MVPでは既存スプレッドシートで管理している全情報を新システムに移行できる状態を目指します。

報酬単価は「時給（税込）」をベースに管理し、業務委託報酬 ＝ 時給 × 時間 ＋ 経費という構造を前提とします。

エリア・言語はスプレッドシートのカラム形式から1行1レコード形式へ変換しますが、移行時の変換が必要な点に注意します。
