# ガイド手配設計資料

## 1. この資料の目的

この資料は、DeepExperienceにおけるガイド手配・報酬精算の方針・データ構造・ステータス管理・管理画面を整理するための資料です。

催行回が確定したあとに「誰が担当するか」を決めるプロセスと、ツアー後の報酬・経費精算プロセスを管理します。

## 3. 初期MVPの基本方針

### 3-1. MVPで実現すること

- 催行回単位でガイドを手配できる（直接アサイン / 募集の2方式）
- 募集方式では、TourOptionの言語・エリア条件を基に対象ガイドを絞り込み、ガイドアプリに通知を送れる
- 募集に対してガイドが応募でき、運営が応募者一覧からアサインできる
- アサインされたガイドがアプリで確認ボタンを押すまでは、運営がアサインを解除して別のガイドに変更できる
- 手配ステータス（未手配 / 募集中 / アサイン済み / 確定 / キャンセル）を管理できる
- 基本は1催行回1ガイドだが、複数ガイドのアサインにも対応できる
- 複数ガイドの場合は役割（メインガイド / サブガイド）を管理できる
- 手配・精算の情報を一元管理できる
- 報酬・経費の見込みを予約確定時点で記録し、ツアー後に実績との差異を確認できる
- 変更・キャンセル発生時に精算レコードを再作成できる

### 3-2. MVPではやらないこと

- ガイドの稼働カレンダーや空き状況の自動チェック
- アサイン候補の自動レコメンド
- 報酬の自動支払い処理

## 4. 全体像

催行回・ガイド手配・精算の関係は以下のとおりです。

```
催行回レコード
  └── ガイド手配レコード（1〜複数）
        ├── ガイドレコード（参照）
        ├── 募集設定レコード（募集方式の場合のみ）
        │     └── 応募レコード（0〜複数）
        └── ガイド精算レコード（1〜複数）
              ← 変更・キャンセルのたびに新しい精算レコードを積む
```

- 1つの催行回には、1件以上のガイド手配レコードが紐付く
- 通常は1件（メインガイド1名）だが、複数名が必要な場合も管理できる
- 募集方式の場合、手配レコードに募集設定レコードが紐付き、応募レコードを管理する
- 1つの手配レコードに、精算レコードが1件以上紐付く

## 5. 手配方式

「手配する」操作を起点に、以下の2方式から選択する。

| 方式 | 内容 |
| --- | --- |
| **直接アサイン** | 特定のガイドを指名してアサインする。ガイドのアプリに通知が届く |
| **募集** | TourOptionの言語・エリア条件（変更可能）で対象ガイドを絞り込み、ガイドアプリに募集通知を送る。応募が来た後に運営がアサインする |

---

## 6. 手配ステータス（手配レコード個別）

※ 運営管理画面§2-1の二層区別に対応。本§6は手配レコード個別の「手配ステータス」、§6-1は催行回レベルの画面表示用「手配状況」。

| ステータス | 意味 | 主な遷移 |
| --- | --- | --- |
| 未手配 | まだ手配が開始されていない | → 募集中（募集方式）または → アサイン済み（直接アサイン）|
| 募集中 | 募集通知をガイドアプリに送信済み。応募を受け付けている状態 | → アサイン済み |
| アサイン済み | 運営がガイドをアサイン済み。ガイドの確認待ち | → 確定（ガイドが確認）または → 未手配 / 募集中（確認前に解除）|
| 確定 | ガイドがアプリで確認ボタンを押し、アサインが確定した状態 | → キャンセル |
| キャンセル | アサインが取り消された状態 | → 未手配（再手配が必要）|

### 6-1. 手配状況（催行回レベル・画面表示用）

催行回一覧では、各催行回の手配状況を以下のように表示します。

| 催行回の手配状況（表示ラベル） | 条件 |
| --- | --- |
| 未手配 | ガイド手配レコードが存在しない、または全件「未手配」 |
| 募集中 | 1件以上が「募集中」で、アサイン済み・確定が0件 |
| アサイン済み | 1件以上が「アサイン済み」で、確定が0件（ガイド確認待ち）|
| 一部確定 | 複数ガイド手配で、確定が1件以上あるが全件未確定 |
| 確定済み | 必要なガイド手配レコードが全件「確定」 |
| 要確認 | キャンセルが発生した場合、または予約変更（日時変更・増員・減員）により再手配要否フラグがON |

| 手配日時 | 手配レコードの作成日時 | |
| アサイン日時 | ステータスが「アサイン済み」に変わった日時 | |
| 確定日時 | ステータスが「確定」に変わった日時 | |

| 変更理由区分 | 再手配要否フラグがONになった理由 | 日時変更 / 増員 / 減員 / ガイド都合 / その他 |
| 適用時給 | 実際に適用する時給（アサイン時に入力・記録。基本時給を初期表示し、特定TourOptionで異なる単価が必要な場合はアサイン時に手動で上書きする。個別単価の専用レコードは持たない。ガイド確認による確定時点でこの値が確定値となる） | ガイドの基本時給を参照して確認。手動上書きも可 |
| 手配メモ | 調整内容・注意事項などの自由記述 | |

### 7-2. 適用時給の参照方針

アサイン時に、ガイドレコードの基本時給を初期表示し、手配レコードに入力・記録します。個別単価の専用レコードは持たず、特定TourOptionで基本時給と異なる単価が必要な場合は、アサイン時に運営が適用時給を手動で上書きする運用とします（個別交渉結果を反映するため）。ガイド確認による確定時点で、この値が確定値となります。

## 8. 募集設定レコード

募集方式を選択した場合に作成されるレコード。催行回の役割枠（メイン／サブ）に対して作成する。メインとサブを同時に募集する場合は、ガイドアプリに1件の案件として表示し、1つの募集で両役割を扱う（ガイドは応募時に役割を選ぶ）。

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 募集ID | システムで自動生成する内部ID | |
| 手配ID | 紐付く手配レコードのID（役割枠ごと） | 両役割を同時募集する場合はメイン・サブ両方の手配レコードに紐付く |
| 募集役割 | この募集で募集する役割 | メインガイド / サブガイド / 両方（メイン＋サブ同時） |
| 言語条件 | 募集対象とする対応言語 | TourOptionのデフォルト値から変更可能 |
| エリア条件 | 募集対象とする対応エリア | TourOptionのデフォルト値から変更可能 |
| 応募締切設定 | あり / なし | |
| 応募締切日時 | 締切ありの場合のみ設定 | |
| 募集ステータス | 募集中 / 締切済み / キャンセル | |
| 作成日時 | | |
| 担当者 | 募集を設定した運営担当者 | |

### 8-1. 応募締切の運用

| 設定 | 用途 | 運用 |
| --- | --- | --- |
| **締切なし** | 急募。応募が来次第アサインできる | 応募が来たタイミングで随時確認・アサイン |
| **締切あり** | 通常案件。まとめて応募を受け付けてからアサイン | 締切後に応募者一覧からアサイン。応募がなければ締切を延長できる |

## 9. 応募レコード

募集に対してガイドが応募するたびに作成されるレコード。

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 応募ID | システムで自動生成する内部ID | |
| 募集ID | 紐付く募集設定レコードのID | |
| ガイドID | 応募したガイドのID | |
| 応募役割 | このガイドが応募した役割 | メインガイド / サブガイド / 両方（同時募集時のみ両方を選択可能） |
| 応募日時 | | |
| 非表示フラグ | このガイドのアプリからこの募集を非表示にするかどうか | ONにするとガイドには募集が消えたように見える |
| アサイン状態 | 候補 / アサイン済み / 非選択 | **役割枠ごとに判定する。** ある役割枠にアサインが確定すると、その役割に応募していた他の応募は「非選択」になる（別の役割枠は独立して募集継続）。両方に応募した応募者は、片方の役割に確定するともう片方の役割では「非選択」になる。アサイン解除時は「候補」に戻る |

### 9-1. 非表示フラグの用途

締切延長などで他の応募を待ちたい場合、特定の応募者のアプリからこの募集を非表示にできる。そのガイドには募集が自然に消えたように見えるだけで、選外になったことや募集が継続していることを気づかせない配慮のための機能。

## 10. ガイド精算レコード

### 10-1. 精算レコードの目的と構造方針

ガイド精算レコードは、1件の手配に対して発生する報酬・経費の記録です。変更・キャンセルによって金額が変わるたびに新しい精算レコードを作成し、履歴として積み上げます。既存の精算レコードは上書きしません。

**業務委託報酬の構造：**

```
業務委託支払合計 ＝ 最終ガイド時給報酬
              ＋ 飲食費補助
              ＋ ガイド経費・その他経費
              ＋ 通勤交通費
              ＋ ゲスト立替経費
```

**ゲスト立替経費について：**  
ゲストがツアー料金の一部として事前にDeepへ支払った金額のうち、ガイドが現地で使用する分をDeepがガイドへ払い出す項目です。参加人数の増減によって金額が変わります。

### 10-2. 管理項目

#### 識別・種別

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 精算ID | システムで自動生成する内部ID | |
| 手配ID | 紐付く手配レコードのID | |
| 催行回ID | 紐付く催行回の内部ID（参照用） | |
| 精算種別 | 初回精算 / 変更による再精算 / キャンセルによる精算 | |
| 精算ステータス | 見込み設定済み / 実績入力待ち / 確認待ち / 確定 | 下記参照 |
| 変更・精算理由メモ | 再精算・キャンセル精算の場合の理由 | |

#### 報酬（見込み）

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 催行時間（見込み） | 原価表等から反映した想定稼働時間 | 予約確定時に設定 |
| 適用時給 | 手配レコードから引き継ぐ時給 | ガイドアサイン確定時に反映 |
| ガイド時給報酬（見込み） | 適用時給 × 催行時間（見込み）で自動計算 | |

#### 報酬（実績）

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 催行時間（実績） | **ガイドは入力しない**。原則として規定時間（見込み）内で催行するため、実績は規定時間で固定。延長は不可抗力時に運営が判断し「催行時間（運営修正）」で変更する | 空＝規定時間を使用 |
| 催行時間（実績）備考 | ガイドが延長理由を申告する備考（数値入力なし・備考のみ）。運営が不可抗力に当たるかを判断する材料 | 悪天候等の不可抗力を想定 |
| 催行時間（運営修正） | 運営のみが入力可。ガイド備考の不可抗力を認めた場合に規定時間から変更する | 通常は空（規定時間） |
| 最終ガイド時給報酬 | 適用時給 × 催行時間（運営修正があればその値、なければ規定時間）で自動計算 | |

| 通勤交通費（見込み） | 原価表から反映 | |
| ゲスト立替経費（見込み） | 予約確定時の参加人数ベースで計算 | |

### 10-3. 実績入力のルール

| 項目 | 入力者 | 入力ルール |
| --- | --- | --- |
| 催行時間（実績） | — | **ガイドは入力しない**。規定時間で固定。ガイドは延長理由を備考のみ申告できる |

| ガイド経費・その他経費（実績） | ガイド | 見込みと異なった場合のみ入力。空の場合は見込みを使用。レシート提出は不要 |
| **通勤交通費（実績）** | **ガイド** | **必須入力。毎回変わるため常にガイドが実績を入力** |
| ゲスト立替経費（実績） | ガイド | 参加人数が変わった場合のみ入力。空の場合は見込みを使用 |

### 10-4. ツアー後精算：運営費（ガイド精算以外）

ガイド精算（業務委託報酬）とは別に、ツアー実施に伴う運営費の実績を運営が入力します。

OTA経由予約がある催行回ではOTAチャネル手数料の確定額を、施設への直接支払いがある場合は施設費の実績を記録します。見込みと実績が一致する場合は入力不要とし、差異がある場合のみ実績を入力します。

#### 運営費精算の管理項目

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| OTAチャネル手数料（見込み） | 原価表・OTA契約から反映 | OTA経由予約がある場合のみ |
| OTAチャネル手数料（実績） | OTA側の確定請求額 | 見込みと異なる場合のみ入力 |
| OTAチャネル手数料備考 | 差異理由・メモ | |
| OTAペナルティ（運営都合違約金） | 運営都合キャンセルでOTAから課された違約金の確定額 | 発生時のみ入力。チャネル手数料とは別の独立科目として原価計上し粗利から差し引く。原価計上はこの運営費精算側に一本化する（支払い側・変更／キャンセルレコードに重複計上しない） |
| OTAペナルティ備考 | 対象予約・算出根拠・確認状況メモ | |
| 施設費（見込み） | 原価表から反映 | 施設への直接支払いがある場合 |
| 施設費（実績） | 実際の施設支払い額 | 見込みと異なる場合のみ入力 |
| 施設費備考 | 差異理由 | |
| その他運営費（見込み） | 原価表から反映 | |
| その他運営費（実績） | 実際に発生した運営費 | 見込みと異なる場合のみ入力 |
| その他運営費備考 | | |
| 運営費確認者 | 確認した運営担当者 | |
| 運営費確認日時 | | |

運営費精算の実績入力はツアー後に運営が行い、ガイド精算の確認と同じタイミングで確定します。

## 11. 精算ステータスと精算フロー

### 11-1. 精算ステータス

| ステータス | 意味 |
| --- | --- |
| 見込み設定済み | 予約確定後、原価表から見込み経費が反映された状態。ガイドアサイン後は時給も反映 |
| 実績入力待ち | ツアー実施後、ガイドの実績入力待ち |
| 確認待ち | ガイドが実績・差異を入力済み。運営による妥当性確認待ち |
| 確定 | 運営確認完了。精算額が確定した状態 |

### 11-2. 精算フロー

```
予約確定
  └→ 精算レコード作成（種別：初回精算 / ステータス：見込み設定済み）
       原価表から見込み経費（飲食費補助・ガイド経費・通勤交通費・ゲスト立替経費）を反映

ガイドアサイン確定
  └→ 同じ精算レコードに適用時給を追記
     ガイド時給報酬（見込み）が自動計算される

ツアー実施後
  └→ 精算ステータスを「実績入力待ち」に変更
  └→ ガイドが実績を入力
       ・通勤交通費（実績）：必須入力
       ・その他項目：見込みと異なった場合のみ差異を入力
  └→ 精算ステータスが「確認待ち」に変わる

運営による確認
  └→ 運営が差異・実績の妥当性を確認
  └→ 問題なければ精算ステータスを「確定」に変更
     確定後は支払い処理へ（MVPでは別管理）
```

### 11-3. 変更・キャンセル発生時の精算

変更・キャンセルが発生した場合は、新しい精算レコードを作成します。

| 発生イベント | 精算レコードの扱い |
| --- | --- |
| 日時変更 | 交通費・催行時間の見込みが変わる可能性があれば、新しい精算レコードを「変更による再精算」として作成 |
| 人数変更（増減） | ゲスト立替経費の見込みが変わるため、新しい精算レコードを「変更による再精算」として作成 |
| キャンセル（催行回中止） | 新しい精算レコードを「キャンセルによる精算」として作成。報酬・経費を0または一部精算に更新 |

既存の精算レコードは削除・上書きしません。最新の「確定」または最新の精算レコードを有効な精算として扱います。

## 12. 手配フロー

### 12-1. 直接アサインフロー

1. 催行回が確定紐付けになる
2. 精算レコードが作成され、原価表から見込み経費が反映される
3. 運営が「手配する」→「直接アサイン」を選択し、ガイドを指名する
4. 手配ステータスが「アサイン済み」になり、ガイドのアプリに通知が届く
5. ガイドがアプリで確認ボタンを押す → 手配ステータスが「確定」になる
6. アサイン時に入力した適用時給が確定値となり、精算レコードに反映される
7. ガイドが確認ボタンを押す前であれば、運営はアサインを解除して別のガイドに変更できる

### 12-2. 募集フロー

1. 催行回が確定紐付けになる
2. 精算レコードが作成され、原価表から見込み経費が反映される
3. 運営が「手配する」→「募集」を選択する
4. 募集設定を行う：
   - 募集役割を選ぶ（メインのみ / サブのみ / メイン＋サブ同時）
   - 言語条件・エリア条件を確認（TourOptionからデフォルト設定。変更可能）
   - 応募締切を設定する（あり / なし）
5. 設定した条件に合致するガイドのアプリに募集通知が届く（メイン＋サブ同時募集は1件の案件として表示）
6. ガイドが応募する（同時募集の場合はメイン / サブ / 両方を選んで応募）。運営は応募者一覧を確認できる
7. 応募者の質が低く他の応募を待ちたい場合、その応募者のアプリからこの募集を非表示にできる（そのガイドには募集が自然に消えたように見える）
8. 締切ありの場合：締切後に応募者一覧からアサインする。応募がなければ締切を延長できる
9. 締切なしの場合：応募が来次第、随時アサインできる
10. 運営が応募者一覧から役割枠ごとに1名を選んでアサインする → その役割枠の手配ステータスが「アサイン済み」になる。同じ役割に応募していた他の応募者はその役割で「非選択」になる（別の役割枠は独立して募集継続）。両方に応募していた応募者は片方の役割に確定すると他方では非選択。アサイン解除時は「候補」に戻る
11. アサインされたガイドのアプリに通知が届く
12. ガイドがアプリで確認ボタンを押す → 手配ステータスが「確定」になる
13. アサイン時に入力した適用時給が確定値となり、精算レコードに反映される
14. ガイドが確認ボタンを押す前であれば、運営はアサインを解除して別の応募者に変更できる

### 12-3. 複数ガイド手配

1. 催行回に対してガイド手配レコードを複数作成する
2. 1件目の役割を「メインガイド」、2件目以降を「サブガイド」として設定
3. 各手配レコードが個別にステータスと精算レコードを持つ

### 12-4. TourOptionバージョン分裂で同日時・同言語に催行回が並立した場合の手配

提供内容の実体改訂で新しいTourOption ID（TourOptionバージョン）が発行され、旧TourOptionバージョン・新TourOptionバージョンそれぞれにピン留めされた予約が存在すると、同じツアー日時・同じゲスト言語でも別々のTourOption ID（TourOptionバージョン）を持つ催行回が2本立つことがあります（束ね鍵＝TourOption ID（TourOptionバージョン）＋ツアー日時＋ゲスト言語の完全一致のため、TourOptionバージョンが異なれば別催行回として分かれる。TourOptionバージョン混在は禁止）。この場合の手配・精算の扱いは以下のとおりです。

- **原則：別催行回＝別手配・別精算。** 並立した2本の催行回は、データ上それぞれ独立した催行回レコード（別々のTourOption ID／別々の催行回ID）であり、ガイド手配レコードも精算レコードもそれぞれ独立して作成・管理します。1催行回1ガイド（複数手配時はメイン／サブ）・精算は催行回単位、という原則は維持します。
- **例外：1ガイドによる弱い共催（OD-4=B）。** 現場では1名のガイドが並立した両催行回を同時に担当できます。ただしデータ上は別催行回・別手配・別精算のまま据え置き、運用上の連絡・調整は各手配レコードの**手配メモ**に「同日時・同言語の別TourOptionバージョン催行回（催行回ID）と1ガイドが兼任」である旨を相互に記録して紐付けます（手配メモ運用）。各手配レコードは個別のステータスを持ち、精算は催行回単位でそれぞれ確定します。
- 催行回レコードを1本に統合したり、TourOptionバージョン混在の予約を1催行回にまとめることはしません。共催を正式に1つの単位として扱う「共催グループ」概念の導入は将来フェーズとします。
- 最少催行人数の未達は自動中止せず、運用アラートで別途検知します（要別設計）。TourOptionバージョン分裂で各催行回の参加人数が分かれることで未達が起きうるため、手配判断時に運用で確認します。

### 12-5. 手配キャンセル・再手配

ガイドが確定後にキャンセルした場合：

1. 当該手配レコードのステータスを「キャンセル」に変更し、理由を記録する
2. 催行回の手配状況が「要確認」になる
3. 新しい手配レコードを作成し、別ガイドを再手配する
4. 精算レコードを「キャンセルによる精算」として新規作成する

既存の手配レコード・精算レコードは削除せず履歴として保持します。

## 13. 変更・キャンセルとの連携

変更・キャンセル設計資料で定義した各処理が発生した場合の影響は以下のとおりです。

| 処理 | 手配への影響 | 精算への影響 |
| --- | --- | --- |
| 日時変更 | 担当ガイドに変更後の日時を確認・連絡。手配メモに記録 | 交通費や催行時間が変わる場合、再精算レコードを作成 |
| 人数変更（増員） | 複数ガイドが必要になる場合は追加手配 | ゲスト立替経費が変わるため再精算レコードを作成 |
| 人数変更（減員） | 手配済みガイドの継続可否を確認。手配メモに記録 | ゲスト立替経費が変わるため再精算レコードを作成 |
| キャンセル（催行回中止） | 手配レコードをキャンセル理由「催行回中止」でキャンセルに変更。アサイン済みガイドへの通知要否フラグを立てる | キャンセル精算レコードを作成。チャネル手数料・施設費など運営費の実績も確認・入力する |
| キャンセル（一部・全部・催行回存続） | ガイド手配を維持する（キャンセルしない）。再手配要否フラグをONにし、変更理由区分「減員」を記録する | 人数変動があれば再精算レコードを作成 |

---

## 14. 管理画面・機能

### 14-1. 催行回詳細画面内のガイド手配セクション

催行回詳細画面にガイド手配・精算を確認・操作するセクションを設けます。

表示内容：

- 手配対象催行回のサマリー（ツアー日時・TourOption名・ゲスト言語・人数）。サマリーには人間可読な**TourOptionバージョンラベル（TourOptionバージョン連番・発効日）**を補助表示し、どのTourOptionバージョン（TourOption ID）の催行回を手配しているかを示す（OD-6=A。一覧の常時列や生IDの表示はしない）。TourOptionバージョン分裂で同日時・同言語の別TourOptionバージョン催行回が並立している場合は、TourOptionバージョンラベルで識別できるようにする
- 現在の手配状況（未手配 / 募集中 / アサイン済み / 一部確定 / 確定済み / 要確認）
- 手配中のガイド一覧（ガイド名、役割、ステータス、ガイド確認ステータス、適用時給）
- 精算状況（最新の精算レコードのステータス・支払合計見込み）
- 手配レコードの追加・編集ボタン
- キャンセル済み手配の履歴表示（折りたたみ可）

### 14-2. 手配方式選択・設定画面

「手配する」ボタンから遷移する画面。

**直接アサインを選択した場合：**
- ガイド検索・選択（ガイドID・氏名・エリア・言語・スキルランクで絞り込み）
- 役割の選択（メインガイド / サブガイド）
- 適用時給の確認・入力
- 手配メモの入力
- アサイン実行

**募集を選択した場合：**
- 言語条件の確認・変更（TourOptionデフォルト値を初期表示）
- エリア条件の確認・変更（TourOptionデフォルト値を初期表示）
- 応募締切の設定（あり / なし）
- 締切ありの場合：締切日時を入力
- 募集開始（対象ガイドへ通知）

### 14-3. 応募者一覧画面

募集方式の場合に参照する画面。募集設定レコードに紐付く応募者を一覧表示する。

表示内容：

- 応募者一覧（ガイド名、応募日時、対応言語、対応エリア、スキルランク、応募役割）
- 各応募者への操作：役割枠ごとのアサイン / 募集を非表示にする
- 対象催行回サマリーにTourOptionバージョンラベル（TourOptionバージョン連番・発効日）を補助表示する（OD-6=A）。TourOptionバージョン分裂で同日時・同言語の別TourOptionバージョン催行回が並立している場合に、どのTourOptionバージョンの催行回への募集かを識別できるようにする
- 同時募集の場合、対象催行回サマリーに募集役割（メイン・サブ）を表示
- 募集設定の確認（言語・エリア条件、応募締切）
- 締切延長ボタン（締切ありの場合）

### 14-4. 精算入力画面（ガイド向け）

ツアー後にガイドが実績を入力する画面です。

表示・入力内容：

- 各項目の見込み額を表示（読み取り専用）
- 催行時間：実績の数値入力はできない（規定時間で固定）。延長があった場合は**備考のみ**で理由を申告（運営が不可抗力かを判断）
- 通勤交通費（実績）：必須入力欄
- その他項目（飲食費補助・ガイド経費・ゲスト立替経費）：見込みと異なった場合のみ実績と備考を入力。ガイド経費はレシート提出不要
- 差異がある場合は理由の入力を求める
- 入力完了後に「提出」操作 → 精算ステータスが「確認待ち」に変わる

### 14-5. 精算確認画面（運営向け）

運営が精算内容の妥当性を確認・確定する画面です。

表示・操作内容：

- 見込みと実績の比較表示（差異がある項目をハイライト）
- 差異に対するガイドの備考・理由の確認
- 催行時間の延長申告（ガイド備考）を確認し、不可抗力と認める場合は運営が催行時間を修正してガイド時給報酬を再計算する
- 業務委託支払合計（ゲスト立替の返金を含む）の確認
- OTAチャネル手数料・施設費・その他運営費の実績入力（見込みと差異がある場合）
- 運営費の確認・確定
- 「確定」操作 → 精算ステータスが「確定」に変わる
- 「差異について確認する」操作 → コメントを追加してガイドに差異確認を依頼（精算ステータスは「確認待ち」のまま）
- 「修正入力」操作 → 運営が値を直接修正して確定
- 「差戻し」操作（ガイドに再入力を依頼する場合）。差戻し後は精算ステータスが「実績入力待ち」に戻る

※ 画面要件の正本は運営管理画面設計資料§3-10。アクションは上記4種（確定 / 差異について確認する / 修正入力 / 差戻し）で揃える。

### 14-6. 精算一覧・履歴

- 手配単位で精算レコード一覧を表示
- 初回精算・再精算・キャンセル精算の履歴を時系列で確認
- 最新の有効な精算レコードを強調表示

### 14-7. 手配状況ダッシュボード（一覧）

催行回一覧に手配状況・精算状況列を追加し、以下を確認できるようにします。

- 催行回日時・TourOption名
- 手配状況（未手配 / 募集中 / アサイン済み / 一部確定 / 確定済み / 要確認）
- 精算状況（見込み設定済み / 実績入力待ち / 確認待ち / 確定）
- 確定ガイド名（確定済みの場合）
- 絞り込み：手配状況・精算状況別フィルター

### 14-8. ガイド詳細画面内の手配履歴タブ

- このガイドが担当した（または担当予定の）催行回一覧
- 各催行回の日時・TourOptionコード・手配ステータス・精算ステータス
- キャンセル済み手配も含む

### 14-9. ガイド向け 報酬管理・支払明細（月次集計）

ガイドが自分の報酬・支払いを確認する画面群。**業務委託報酬のガイド向け表示**であり、二層分離（施設マスター・原価項目設計資料 §11）に従う（立替分も含め全額を「報酬」として表示。内部の原価科目分離は別レイヤー）。

> **ガイド向け表示名 ↔ 内部用語の対応**：「ツアー報酬」＝内部の**ガイド時給報酬**（適用時給×催行時間。ガイド画面の算定根拠は「基準単価 × 標準所要時間」と表示し、「時給」の語は出さない）／「現地までの交通費（往復）」＝内部の**通勤交通費**（人件費区分）／「移動交通費（ツアー中）」＝ツアー経費側の実費精算型。精算・原価レコードでは従来の内部用語（適用時給・通勤交通費 等）を用いる。

**報酬管理（月次一覧）**

- 月別に、担当ツアーごとの**報酬合計**（ツアー報酬 ＋ 現地までの交通費（往復）＋ ツアー経費〔立替・実費〕）を一覧表示
- 月次サマリー：担当件数 ／ 報酬合計（ツアー報酬 ＋ その他支払項目）
- ツアーに紐づかない**その他支払項目（運営登録：研修交通費・翻訳費等）**を別セクションで表示。ガイドは閲覧専用で、相違があれば「相違を報告」（ガイドからの申請フローは持たない）

**報酬詳細（ツアー単位）**

- 報酬の内訳（ツアー報酬〔基準単価×標準所要時間で算定〕／ 現地までの交通費（往復）／ ツアー経費〔立替・実費〕）を表示
- ツアー経費はTourOption原価設定から**自動反映**。単価確定型は自動表示（差異時のみ「修正」＋理由）、**実費精算型と現地までの交通費（往復）はガイドが実費入力**（§14-4 の精算入力と連携）。領収書は任意
- 立替費目は「ゲスト分立替経費 ／ ガイド分立替経費 ／ その他（実費精算）」で表示（呼称↔支払区分の対応は 施設マスター・原価項目設計資料 §11-2）

**支払明細書（月次）**

- 確定した月次の**支払総額** ＝ ツアー報酬合計 ＋ その他支払項目（運営登録）
- ツアーごとの報酬内訳を明細表示。印刷／PDF出力に対応
- 個人情報の表示は §11-5（施設マスター・原価項目設計資料）に従う（実績・確定後の画面のため氏名表示可。支払明細は氏名を出さずツアー名で識別してもよい）

**データの源泉・関連**

- 集計の元データはガイド精算レコード（§10）の見込み／実績。実績確定（§11 精算フロー）後に支払明細へ反映
- 月次の確定支払処理（自動支払）は対象外（§15）。経理向けの手動振込管理・「振込済」記録は §14-10。画面要件の詳細・粒度はMVP実装で確定

### 14-10. ガイド報酬の支払・振込管理（運営・経理向け）

確定したガイド業務委託報酬を**経理部がガイド別に把握し、振込を実行・記録する**画面。§14-9 が同じ確定データを**ガイドに見せる**明細であるのに対し、本節はその裏側＝**対経理オペレーション**を扱う。

> **スコープ境界（重要）**：本画面は**手動振込の集約・可視化・「振込済」記録・監査証跡**に限定する。経理は自行のネットバンキング等で実送金し、本画面では振込済をチェックオフして記録・ロックするだけ。銀行API／支払基盤と連携してシステムが送金を自動実行する「報酬の自動支払い処理」は対象外（§15）。これはゲスト決済で確立済みの「実行は外部・記録は内部」方針（支払い・決済管理設計資料）のガイド支払版であり、自動支払処理とは別物。

**支払サイクルと対象月**

- 既定の流れ：**当月催行分 → 翌月締め → 翌月振込**（締め日・振込日は運用パラメータとして保持。**具体日付は要業務確認**のため資料に固定しない）。
- 画面の月セレクタは **「支払対象月（振込月）」** を基準とする。§10-5（売上・原価管理設計資料）の月次締めが**催行月**ベースであるのと用語が衝突するため、本画面では明示的に「支払対象月」とラベリングして区別する。
- 1ガイドの1支払対象月に**複数の催行月分**（遅れて確定した前月分など）が混在しうるため、明細には**催行月・催行回（TI-…）**を併記して内訳を辿れるようにする。

**支払対象の生成元**

- 対象は **「確定」済みガイド精算レコード（§10／§11 精算フロー）** ＋ 当月の **その他支払項目（運営登録：研修交通費・翻訳費 等）**。未確定・差戻し中の精算は集計に含めない。
- **月次締め（粗利確定）とは疎結合**：精算が「確定」していれば月次締め未完でも振込対象に載せる。締め状態は本画面に**参照表示**するに留める（経理の振込サイクルと社内の粗利締めは別運用）。

**集計単位と支払総額**

- **ガイド（G-NNN）× 支払対象月 ＝ 1支払行**。
- 支払総額（＝振込額）＝ §14-9 の支払明細書の定義に一致：
  - **ツアー報酬合計**（Σ 各確定催行回のガイド報酬＝ツアー報酬〔内部：ガイド時給報酬＝適用時給×催行時間〕＋ 現地までの交通費（往復）〔内部：通勤交通費〕＋ ツアー経費〔立替・実費〕）
  - ＋ **その他支払項目（運営登録）**
- 表示は §14-9 のガイド向け呼称を用い、内部用語（適用時給・通勤交通費 等）は出さない（§11 二層分離）。

**支払ステータス**

| ステータス | 意味 | 遷移 |
| --- | --- | --- |
| 未振込 | 金額確定済み・未振込（既定の初期状態） | ←→ 保留 ／ → 振込済 |
| 振込済 | 経理が自行で実振込しチェックオフ済み。**ロック**（後述） | 限定取消のみ |
| 保留 | 当月は振り込まない（口座確認中・係争・本人都合 等／理由メモ） | ←→ 未振込 |

- 補助フラグ（ステータスと独立）：`口座未登録`・`金額0／マイナス` は**振込不可**（バッチ対象外）。
- **承認ステップは設けない**（未振込→振込済の1段。実送金は銀行側で二重承認済み）。将来 `準備中（CSV出力済み等）→ 承認 → 振込済` を差し込めるよう状態を拡張可能にしておく。

**ロック・冪等・監査（snapshot-at-payment）**

- 振込済化の瞬間に、**支払総額・内訳・対象催行回ID（TI-…）・振込先口座**を**確定時点でスナップショット凍結**する。以後に元の精算が差戻し・再確定されても、**当月の振込済額は遡及変更しない**。
- 冪等キー＝**ガイドID＋支払対象月**（同一ガイド・同一支払対象月の二重振込登録を防ぐ）。
- 監査証跡：**振込実行日時／振込実行日／実行者／参照番号／対象内訳スナップショット**を記録（精算確認・金額確認の確定ログと同方針）。
- 誤操作対応として**限定取消**（理由必須・監査ログ残置）を許容。支払後に精算が変動した差額は、当月の遡及修正ではなく**翌月のその他支払項目（運営登録）／調整**で処理する。

**二層分離の整合**

- 本画面が表示・振込するのは**ガイド向け表示の総額（＝振込額）**のみ。内部の原価科目分離（ガイド人件費／施設費／単発経費）は売上・原価レコード側（売上・原価管理設計資料 §6-2）で計上され、本画面には現れない。
- したがって本画面の「支払総額」と収支系画面の「ガイド報酬原価」は、立替分の科目振替により**一致しないことがある**（仕様であり矛盾ではない）。展開明細に注記する。

**インボイス・源泉徴収の表示**

- インボイス登録状況（適格／未登録。登録番号は ガイド情報設計資料 §6）は**表示フラグのみ**。MVPでは振込額に影響させない（仕入税額控除の経過措置・消費税区分の計算は将来）。
- 源泉徴収は**自動計算しない**（表示・注記のみ）。個人外注への報酬は源泉徴収義務の対象になりうるが、**対象可否・税率は業務の性質・契約形態（個人／法人）により異なるため要業務確認**（資料に税率・対象号は書かない）。
- 関連：ガイドマスタに「個人／法人」事業者区分フィールドが現状未定義。**追加要否を要検討**。

**出力**

- **支払明細PDF**（§14-9 のPDF出力方針に整合）。
- **汎用CSV**（列：ガイドID・氏名・銀行名・支店番号・口座種別・口座番号・口座名義・振込額・インボイス番号・支払対象月）。経理が自行へ手入力／取込する際の照合・記帳補助。送金実行は行わない。
- 全銀協フォーマット（総合振込FBデータ）は**将来**（固定長・半角カナ等の厳密仕様、銀行別検証コストが大きいため）。CSVの口座情報は将来の全銀変換を見据えて構造化して持つ。

**画面要件（モック：deep-experience-html/admin/ガイド支払一覧.html）**

- フィルタ：支払対象月／ステータス（全て・未振込・振込済・保留）／検索（G-NNN・氏名）／「口座未登録のみ」。
- サマリー：対象ガイド数／支払総額／未振込／振込済／保留。
- 一覧（1行＝1ガイド・展開式）：ガイド（氏名＋G-NNN）・担当件数・ツアー報酬・その他支払項目・**支払総額**・振込先抜粋・インボイス状況・ステータス・アクション（詳細／振込済／保留）。
- 展開詳細：(A) 当月精算内訳（催行回単位・読み取り・精算確認へリンク）／(B) その他支払項目（運営登録）／(C) 振込情報（振込先全項目・予定日／実行日／実行者／参照番号・二層分離の注記）。
- バッチ：選択 → 振込済にする（確認モーダルで実行日・参照番号）／CSV出力。保留・口座未登録・金額≤0 は選択不可。

**MVP対象外**

- 自動振込（銀行API直結）／源泉・消費税の自動計算／会計ソフト連携／部分振込（partial。例外は保留＋翌月繰越で吸収）。

## 16. 初期MVPの完了条件

**手配**

- 催行回に対して直接アサイン / 募集の2方式で手配を開始できる
- 募集方式でTourOptionの言語・エリア条件を確認・変更して募集設定できる
- 応募締切あり / なしを設定できる
- 締切ありの場合、締切を延長できる
- 対象ガイドのアプリに募集通知を送れる
- 応募者一覧を確認し、特定の応募者のアプリからこの募集を非表示にできる
- 応募者一覧からガイドをアサインできる
- 直接アサインでガイドを指名してアサインできる
- アサインされたガイドがアプリで確認ボタンを押せる
- 運営側でガイドの確認ステータスを確認できる
- ガイドが確認する前であればアサインを解除して別のガイド / 応募者に変更できる
- 手配ステータス（未手配 / 募集中 / アサイン済み / 確定 / キャンセル）を管理できる
- 1催行回に複数ガイドをアサインでき、役割（メインガイド / サブガイド）を設定できる
- 催行回一覧から手配状況を確認できる
- アサイン時に適用時給を入力・記録できる
- アサイン時にガイドの基本時給を初期値として表示できる
- キャンセルされた手配レコードを削除せず履歴として保持できる
- 手配キャンセル後の再手配ができる
- ガイド詳細画面から過去の手配履歴を確認できる

**精算**

- 予約確定時に精算レコードを作成し、見込み経費を反映できる
- ガイドアサイン確定時に適用時給を精算レコードに反映できる
- ガイド時給報酬（見込み・実績）を自動計算できる
- 通勤交通費の実績をガイドが入力できる（必須項目）
- 催行時間はガイドが実績入力できず備考のみ申告でき、延長は不可抗力時に運営が判断・修正できる
- その他項目（飲食費補助・ガイド経費・ゲスト立替経費）の差異をガイドが入力できる
- 差異がない場合は見込み額を使用して合計を計算できる
- 業務委託支払合計を自動計算できる
- 運営が精算内容の妥当性を確認・確定できる
- 変更・キャンセル発生時に新しい精算レコードを作成でき、履歴として保持できる
- 精算レコードの種別（初回精算 / 再精算 / キャンセル精算）を管理できる
- OTAチャネル手数料・施設費・その他運営費の見込みを記録し、ツアー後に実績との差異を入力できる
- 運営費精算をガイド精算と同タイミングで確認・確定できる

## 17. まとめ

ガイド手配は、催行回の確定からツアー実施後の精算完了までを管理します。手配方式は直接アサインと募集の2方式を持ち、募集方式ではガイドアプリへの通知・応募管理・アサインの一連の流れをシステムで管理します。

精算レコードは変更・キャンセルのたびに新規作成して積み上げる構造とし、金額の変化履歴を保持します。見込みと実績の差異管理では、毎回変動する通勤交通費のみガイドに必須入力を求め、その他の項目は差異があった場合のみ入力する運用とすることで、ガイドの入力負担を抑えます。

ゲスト立替経費はゲストからの入金に含まれる通過項目として管理し、参加人数の変動に応じて精算レコードで更新します。
